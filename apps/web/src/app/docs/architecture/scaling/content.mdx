# Scaling

LazyCloud automatically scales your services based on CPU and memory usage.

## Enable Auto-Scaling

Add scaling labels to your service:

```yaml
services:
  api:
    build: .
    deploy:
      labels:
        lazycloud.scaling.enabled: "true"
        lazycloud.scaling.min: "2"
        lazycloud.scaling.max: "10"
        lazycloud.scaling.cpu: "70"
        lazycloud.scaling.memory: "80"
```

This configuration:
- Keeps at least 2 instances running
- Scales up to 10 instances under load
- Adds instances when CPU exceeds 70%
- Adds instances when memory exceeds 80%

## How It Works

LazyCloud monitors your service's resource usage:

1. When usage exceeds the threshold, new instances are added
2. Traffic is automatically distributed across instances
3. When load decreases, instances are removed (down to the minimum)

## Manual Replicas

Without auto-scaling, set a fixed number of replicas:

```yaml
services:
  worker:
    build: .
    deploy:
      replicas: 3
```

This runs exactly 3 instances of the worker service.

<Note>
Auto-scaling is recommended for web services with variable traffic. Use fixed replicas for background workers with predictable load.
</Note>
