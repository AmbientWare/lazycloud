# Secrets

LazyCloud requires you to provide values for all environment variables during deployment. Values are stored encrypted and injected into your containers at runtime.

## Define Variables in Compose

Always define environment variables explicitly in your compose file. This ensures LazyCloud knows which variables your services need:

```yaml
services:
  api:
    environment:
      - DATABASE_URL=${DATABASE_URL}
      - REDIS_URL=${REDIS_URL}
```

<Note>
LazyCloud detects variables from your compose file. If a variable isn't listed, it won't be prompted for or injected.
</Note>

Use YAML anchors to avoid repetition when multiple services share the same variables:

```yaml
x-common-env: &common-env
  DATABASE_URL: ${DATABASE_URL}
  REDIS_URL: ${REDIS_URL}
  NODE_ENV: ${NODE_ENV}

services:
  api:
    build: ./api
    environment:
      <<: *common-env
      API_SECRET: ${API_SECRET}

  worker:
    build: ./worker
    environment:
      <<: *common-env
```

## Local vs Production

Your compose file typically contains local development values:

```yaml
services:
  api:
    build: .
    environment:
      - DATABASE_URL=${DATABASE_URL}
      - OPENAI_API_KEY=${OPENAI_API_KEY}
      - NODE_ENV=development
      - REDIS_URL=redis://localhost:6379
```

For cloud deployment, you need production values. Create a separate `.env.prod` file:

```bash
# .env.prod
DATABASE_URL=postgres://user:pass@prod-db.example.com:5432/myapp
OPENAI_API_KEY=sk-prod-...
NODE_ENV=production
REDIS_URL=redis://cache:6379
```

Then deploy with:

```bash
lazycloud deploy --env .env.prod
```

<Warning>
All environment variables in your compose file must have values in your import source. Deployment will fail if any are missing.
</Warning>

## Import Sources

You can import values from:

- **A file** — `lazycloud deploy --env .env.prod`
- **Your shell** — `lazycloud deploy --env shell` (uses exported variables)

Without the `--env` flag, LazyCloud prompts you to choose a source interactively.

## Recommended Workflow

1. Use `.env` for local development (with `docker compose`)
2. Create `.env.prod` with production values
3. Deploy with `lazycloud deploy --env .env.prod`
4. After initial deploy, manage secrets in the dashboard

<Tip>
Add `.env.prod` to your `.gitignore` to avoid committing production secrets.
</Tip>

## Shared Across Services

Environment variables are shared across all services in a deployment. Define a variable once and all services can access it.

```yaml
services:
  api:
    environment:
      - DATABASE_URL=${DATABASE_URL}

  worker:
    environment:
      - DATABASE_URL=${DATABASE_URL}  # Same value, same secret
```

## Managing Secrets in the Dashboard

After deployment, manage secrets directly in the LazyCloud dashboard:

1. Open the dashboard with `lazycloud dashboard`
2. Navigate to your deployment
3. Go to the **Secrets** section
4. Edit existing values or add new ones

<Tip>
Use the dashboard to rotate API keys or update credentials without redeploying.
</Tip>

## When to Redeploy

- **Updating a secret value** — Edit in the dashboard and restart your services. No redeploy needed.
- **Adding or removing environment variables** — Update your compose file and run `lazycloud deploy` again.
