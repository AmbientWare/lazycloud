# Next.js

A Next.js application using the App Router and standalone output mode. Demonstrates deploying server-rendered React applications with optimized Docker builds.

## Deploy

```bash
git clone https://github.com/AmbientWare/lazycloud-releases.git
cd lazycloud-releases/examples/nextjs

lazycloud init
lazycloud deploy
```

## Usage

Open your deployment URL in a browser. The page is server-rendered on each request.

Health check:

```bash
curl https://your-app.lazycloud.dev/api/health
```

```json
{"status": "healthy"}
```

### next.config.ts

The `standalone` output mode is required for containerized deployments:

```typescript
import type { NextConfig } from "next";

const nextConfig: NextConfig = {
  output: "standalone",
};

export default nextConfig;
```

This produces a self-contained build that doesn't require `node_modules` at runtime.

### Dockerfile

Multi-stage build separating dependencies, build, and runtime:

```dockerfile
FROM node:22-alpine AS builder

WORKDIR /app

COPY package.json ./
RUN npm install

COPY . .
RUN npm run build

FROM node:22-alpine AS runner

WORKDIR /app

ENV NODE_ENV=production

COPY --from=builder /app/.next/standalone ./
COPY --from=builder /app/.next/static ./.next/static

EXPOSE 3000

CMD ["node", "server.js"]
```

The builder stage installs dependencies and runs `next build`. The runner stage contains only the standalone output—no `node_modules` or source files.

### compose.yaml

```yaml
services:
  web:
    build: .
    ports:
      - "3000:3000"
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:3000/api/health"]
      interval: 30s
      timeout: 5s
      retries: 3
```

Port 3000 is exposed as HTTPS. The `/api/health` route is polled for container health monitoring.
