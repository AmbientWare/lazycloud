# LLM Chatbot

A full-stack AI chatbot with streaming responses, showing how LazyCloud handles multi-service apps with persistent storage, resource limits, and secrets.

<Tip>
**What you'll learn:** Multi-service orchestration, streaming API responses, persistent volumes for databases, Redis caching, and encrypted secret handling.
</Tip>

│ Frontend │     │   API    │     │          │

                      │

## Run it

```bash
git clone https://github.com/AmbientWare/lazycloud-releases.git
cd lazycloud-releases/examples/llm-chatbot

# Local
export OPENAI_API_KEY=sk-...
docker compose up --build

# Deploy
lazycloud init
lazycloud deploy
```

## What's configured

This example uses standard Docker Compose with a few LazyCloud labels.

### Environment variables

```yaml
environment:
  - OPENAI_API_KEY=${OPENAI_API_KEY}
  - OPENAI_MODEL=${OPENAI_MODEL:-gpt-4o-mini}
  - REDIS_URL=redis://redis:6379
```

Environment variables defined in your compose file are detected during `lazycloud deploy`. You'll be prompted to import values from a `.env` file, your shell environment, or enter them manually. Values are stored encrypted.

Services can reference each other by name—`redis://redis:6379` resolves to the Redis container automatically.

### Build arguments

```yaml
frontend:
  build:
    context: ./frontend
    args:
      NEXT_PUBLIC_API_URL: http://localhost:8000
```

Build arguments are for values needed at build time. The Next.js frontend uses `NEXT_PUBLIC_API_URL` to know where to send API requests—this gets embedded into the JavaScript bundle during build.

When prompted during `lazycloud deploy`, enter the production value using the `.public` suffix:

```
NEXT_PUBLIC_API_URL: https://api.public
```

LazyCloud transforms `.public` to the actual public URL (e.g., `https://api-abc12.lazycloud.dev`).

### CORS configuration

The API needs to allow requests from the frontend's public URL. The compose file has a local default:

```yaml
api:
  environment:
    - CORS_ORIGINS=http://localhost:3000,http://frontend:3000
```

When prompted during `lazycloud deploy`, enter the production value using the `.public` suffix:

```
CORS_ORIGINS: https://frontend.public
```

LazyCloud transforms `frontend.public` to the actual public URL (e.g., `https://frontend-abc12.lazycloud.dev`).

<Tip>
For server-side code, use the service name directly (e.g., `http://api:8000`). LazyCloud handles DNS resolution automatically.
</Tip>

### Resource limits

```yaml
deploy:
  resources:
    limits:
      cpus: "1.0"
      memory: 512M
    reservations:
      cpus: "0.25"
      memory: 256M
```

Set CPU and memory per service. `limits` caps max usage, `reservations` guarantees minimum resources.

### Persistent storage

```yaml
volumes:
  api-data:
    labels:
      lazycloud.volume.size: "10Gi"
  redis-data:
    labels:
      lazycloud.volume.size: "5Gi"
```

Data persists across deployments and restarts. Each service gets its own volume—SQLite database in `api-data`, Redis cache in `redis-data`.
