# LLM Chatbot

A full-stack AI chatbot with streaming responses, showing how LazyCloud handles multi-service apps with persistent storage, resource limits, and secrets.

<Tip>
**What you'll learn:** Multi-service orchestration, streaming API responses, persistent volumes for databases, Redis caching, and encrypted secret handling.
</Tip>

## Prerequisites

You'll need an **OpenAI API key** to use GPT models.

1. Create an account at [platform.openai.com](https://platform.openai.com)
2. Go to [API Keys](https://platform.openai.com/api-keys)
3. Create a new key and copy it (starts with `sk-`)

## Quick Start (Local)

```bash
git clone https://github.com/AmbientWare/lazycloud-releases.git
cd lazycloud-releases/examples/llm-chatbot

# Set your API key
export OPENAI_API_KEY=sk-your_key_here

# Run locally
docker compose up --build
```

Open [http://localhost:3000](http://localhost:3000) to use the chatbot.

## Deploy to LazyCloud

### Step 1: Initialize

```bash
lazycloud init
```

This detects your `compose.yaml` and prepares for deployment.

### Step 2: Deploy

```bash
lazycloud deploy
```

You'll be prompted for environment variables and build arguments. When asked "Import from", you have three options:

| Option | When to use |
|--------|-------------|
| `file` | Import from a `.env` file (default) |
| `shell` | Import from your current shell environment |
| `manual` | Enter each value directly in the terminal |

Select `manual` to enter values directly.

#### Environment Variables

| Variable | What to enter |
|----------|---------------|
| `OPENAI_API_KEY` | Your OpenAI API key (e.g., `sk-abc123...`) |
| `OPENAI_MODEL` | Model name or keep default `gpt-4o-mini` |
| `REDIS_URL` | Keep the default `redis://redis:6379` |
| `CORS_ORIGINS` | Enter `https://frontend.public` |

#### Build Arguments

| Argument | What to enter |
|----------|---------------|
| `NEXT_PUBLIC_API_URL` | Enter `https://api.public` |

<Tip>
**About `.public` URLs:** LazyCloud transforms `.public` suffixes into actual deployed URLs. Use this pattern when services need to reference each other's public endpoints. For example, `https://frontend.public` becomes the frontend's real URL.
</Tip>

### Step 3: Access your app

Once deployed, run `lazycloud dashboard` to view your deployment. Navigate to each service to find its public URL.

Your chat history persists in SQLite, and Redis provides caching across sessions.

## Configuration Reference

Details about the `compose.yaml` configuration for customization.

### Environment variables

```yaml
environment:
  - OPENAI_API_KEY=${OPENAI_API_KEY}
  - OPENAI_MODEL=${OPENAI_MODEL:-gpt-4o-mini}
  - REDIS_URL=redis://redis:6379
```

Variables are detected during `lazycloud deploy` and stored encrypted. Services can reference each other by name—`redis://redis:6379` resolves automatically.

### Build arguments

```yaml
frontend:
  build:
    context: ./frontend
    args:
      NEXT_PUBLIC_API_URL: http://localhost:8000
```

Build arguments are for values needed at build time. The Next.js frontend uses `NEXT_PUBLIC_API_URL` to know where to send API requests.

### CORS configuration

```yaml
api:
  environment:
    - CORS_ORIGINS=http://localhost:3000,http://frontend:3000
```

The API needs to allow requests from the frontend's public URL. Use `https://frontend.public` for production.

<Tip>
For server-to-server communication, use the service name directly (e.g., `http://api:8000`). LazyCloud handles DNS resolution automatically.
</Tip>

### Persistent storage

```yaml
volumes:
  api-data:
    labels:
      lazycloud.volume.size: "10Gi"
  redis-data:
    labels:
      lazycloud.volume.size: "5Gi"
```

Each service gets its own volume. Data persists across deployments and restarts.

### Resource limits

```yaml
deploy:
  resources:
    limits:
      cpus: "1.0"
      memory: 512M
    reservations:
      cpus: "0.25"
      memory: 256M
```

`limits` caps maximum usage. `reservations` guarantees minimum resources.
