# Resources

Control how much CPU and memory your services can use.

## Setting Resources

Define resource reservations in your compose file:

```yaml
services:
  api:
    build: .
    deploy:
      resources:
        reservations:
          cpus: '0.5'
          memory: 2G
```

## Reservations and Limits

- **Reservations** — Resources guaranteed to your service. This is what you're billed for as a minimum.
- **Limits** — LazyCloud automatically sets limits to 4× your reservations, allowing your service to burst when needed.

For example, reserving 0.5 CPU and 2GB memory gives your service:
- **Guaranteed**: 0.5 CPU, 2GB memory
- **Burst capacity**: Up to 2 CPU, 8GB memory if available

## CPU

CPU is measured in cores:

- `"0.25"` — Quarter core (minimum)
- `"0.5"` — Half a CPU core
- `"1.0"` — One full core
- `"2.0"` — Two cores

## Memory

Memory uses standard units:

- `512M` — 512 megabytes (minimum)
- `1G` — 1 gigabyte
- `2G` — 2 gigabytes
- `4G` — 4 gigabytes

## Resource Ratio

Memory must be between 1-4 GB per CPU core. LazyCloud automatically adjusts your resources to fit this ratio:

| CPU | Memory Range |
|-----|--------------|
| 0.25 | 0.5G - 1G |
| 0.5 | 0.5G - 2G |
| 1.0 | 1G - 4G |
| 2.0 | 2G - 8G |

If you specify resources outside this range, LazyCloud bumps the lower resource up to match.

## Defaults

If you don't specify resources, LazyCloud applies:

- **CPU**: 0.25 cores reserved, 1 core limit
- **Memory**: 1GB reserved, 4GB limit

## Billing

You're billed for the greater of your actual usage or your reservations. This means:

- If you reserve 1 CPU but only use 0.5 CPU, you pay for 1 CPU
- If you reserve 1 CPU but burst to 2 CPU, you pay for 2 CPU

<Tip>
  Start with the defaults and scale up based on actual usage. Check the
  dashboard to monitor your services and optimize costs.
</Tip>
