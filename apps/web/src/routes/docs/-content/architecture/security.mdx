# Security

Every container on LazyCloud runs inside a [gVisor](https://gvisor.dev) sandbox, providing an additional layer of isolation.

## What is gVisor?

gVisor is an application kernel that intercepts system calls from your container. Instead of running directly on the host kernel, your code runs in an isolated sandbox.

This means:

- **Process isolation** — Containers cannot access other containers or the host system
- **Reduced attack surface** — Even if your application has a vulnerability, the blast radius is contained
- **Defense in depth** — Multiple security layers protect your workloads

## Network Isolation

Services are isolated by network. Only services on the same network (defined in your compose file) can communicate with each other.

```yaml
services:
  api:
    networks:
      - internal

  db:
    networks:
      - internal

  frontend:
    networks:
      - public

networks:
  internal:
  public:
```

In this example, `frontend` cannot directly access `db` because they're on different networks.

## Secrets Protection

Environment variables containing sensitive data are:

- Encrypted at rest
- Never logged or exposed in the dashboard
- Only accessible to the services that need them

## TLS Everywhere

All external traffic uses TLS. LazyCloud automatically provisions and renews certificates for your domains.
