Build cache measurements (task notes; removed before the PR merges)

Host: scratch c6a.2xlarge, fleet CPU AMI ami-02261a8bd696ac326 (us-east-2),
100 GiB gp3 root at 3000 IOPS / 125 MiB/s as the launcher gives fleet hosts.
Harness: the agent package's test server on the host, the real agent and
builder, pushing to a scratch ECR repository; layers of the managed base
count as converted, uploads go to a local sink (unchanged by this work).
Times are seconds from the start command; run = RUN steps, export =
"exporting layers", push = "pushing layers", convert = the agent's
conversion of the layers the server names.

Snapshotter: BuildKit already picks overlayfs today. Its state sits on the
image's declared VOLUME, an anonymous Docker volume on the root xfs, removed
with the container. A bind-mounted host directory also gets overlayfs.
tmpfs does not work: whiteouts fail to convert ("unlinkat ... input/output
error"), so the state must be on a disk filesystem.

Export is disk-bound, not compression-bound: uncompressed exports slower
than zstd. iostat during the torch export shows the gp3 root saturated at
125 MiB/s or ~1000 IOPS at queue depth 1 (the RUN step's dirty data and the
blob commit's fsync), with the CPU idle.
