# Standing up and removing an EKS deployment

Terraform owns AWS infrastructure. Argo CD owns cluster workloads from the
deployment branch. The scheduler owns runtime fleet capacity. Pangolin is
external and must exist before the first deploy.

## Stand up

1. Create the Pangolin organization, license, API key, and verified product
   domain listed in `README.md`. Expose the Integration API at
   `pangolin_api_url`.
2. Configure the PlanetScale credentials and GitHub App private key in the
   operator environment.
3. Copy `terraform.tfvars.example` to an untracked `terraform.tfvars` and set the
   deployment, public URLs, Pangolin IDs, Stripe account, and capacity prices.
4. Initialize and apply Terraform.

```sh
terraform -chdir=deploy/platform-eks init \
  -backend-config="bucket=<state-bucket>" \
  -backend-config="key=platform-eks/<deployment>.tfstate" \
  -backend-config="region=us-east-1"
terraform -chdir=deploy/platform-eks apply
```

After a failed apply, inspect AWS directly before retrying. A provider error can
arrive after the external service created a resource that Terraform did not
record.

Write every key declared by `operator_variables` in `secrets.tf` to the operator
Secrets Manager document before Argo's first sync. Connector and machine-client
credentials are generated by the Pangolin bootstrap Job.

Set the deployment workflow secrets:

```sh
gh secret set AWS_DEPLOY_ROLE_ARN \
  --body "$(terraform -chdir=deploy/platform-eks output -raw deploy_role_arn)"
gh secret set TF_STATE_BUCKET --body '<state-bucket>'
```

Publish the first release and deployment:

```sh
gh workflow run ship.yml -f deployment=<deployment>
```

Inspect independent signals while Argo reconciles:

```sh
aws eks update-kubeconfig --name <deployment> --region us-east-1
kubectl -n argocd get applications
kubectl -n lazycloud get pods
kubectl -n lazycloud logs job/pangolin-bootstrap --tail=80
kubectl -n lazycloud logs -l app=pangolin-site -c newt --prefix --tail=80
kubectl -n lazycloud logs -l app=control-plane -c pangolin-client --prefix --tail=80
```

Every Newt site and Pangolin machine client, the control-plane containers, and
bootstrap Jobs must report their own successful state. A Ready API without a
connected Pangolin client cannot reach agents.

## Remove

Destroy runtime fleet capacity through LazyCloud before destroying the cluster.
Terraform does not own the scheduler-created Auto Scaling groups and launch
templates.

```sh
lazycloud-admin fleet destroy
```

Confirm the fleet resources are gone, then remove the PlanetScale role from
state and destroy the module:

```sh
terraform -chdir=deploy/platform-eks state rm \
  planetscale_postgres_branch_role.control_plane
terraform -chdir=deploy/platform-eks destroy
```

The role is removed from state because PlanetScale will not drop a role that
still owns schema objects; deleting the branch removes both.

Terraform does not own runtime workspace buckets, detached EBS volumes, or the
external Pangolin resources. Resolve each exact resource before deleting it.
Never apply this teardown to a persistent production installation without an
approved data-retention plan.
