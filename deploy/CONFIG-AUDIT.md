# Environment and configuration audit

292 distinct names across `compose.yaml`, `.env`, `.env.example` and every
`BaseSettings` class in the repository.

## How each verdict was reached

- Names were resolved to their settings field through the field's **validation alias**,
  not `env_prefix`. Several classes bind names the prefix does not predict; keying on the
  prefix reported 22 live worker variables as unread, and deleting those would have
  silently disabled retention and the cache ceilings on every worker.
- "Redundant" means the settings object was **constructed twice**, with and without the
  Compose value, and produced the same result — not that two strings matched.
- A name whose rendered value **differs between services** is per-instance identity and
  stays a passthrough, however constant it looks in the file.
- A name with no settings field was grepped across `packages`, `apps`, `deploy`, `tests`
  and `docker` before being called dead.
