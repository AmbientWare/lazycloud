Workloads use LazyCloud compute by default. Use these commands to inspect
capacity or connect compute you own. Follow [Compute](/platform/compute)
for setup and host requirements.

## lazycloud compute

```bash
uv run lazycloud compute status       # capacity and the workspace's default pool
uv run lazycloud compute instances    # running instances
uv run lazycloud compute pools        # pools this workspace can use
uv run lazycloud compute workloads    # which pool each workload runs in
uv run lazycloud compute policy show
uv run lazycloud compute policy update --default-pool <pool>
```

## lazycloud cloud

Connecting an AWS account needs the Business plan. The connection belongs to your
account and backs every workspace you own.

```bash
uv run lazycloud cloud connect aws --account-id <id> [--role-arn <arn>]
uv run lazycloud cloud authorize [--profile <aws-profile>]
uv run lazycloud cloud status [--watch] [--until <phase>] [--interval <s>] [--timeout <s>]
uv run lazycloud cloud validate            # recheck the current authorization
uv run lazycloud cloud reconnect  # start a replacement authorization
uv run lazycloud cloud cancel-reconnect
uv run lazycloud cloud retry               # retry the connection's pending action
uv run lazycloud cloud disconnect [--wait]
```

For a managed connection, run `cloud authorize` with your AWS CLI profile after
`cloud connect aws` or `cloud reconnect`. The CLI verifies that the profile
belongs to the connected account, then submits the connection template directly
to CloudFormation. Run `cloud validate` after the stack finishes. Your AWS
credentials stay on your machine.

`cloud status --until` accepts `awaiting_authorization`, `validating`,
`ready`, `degraded`, `reconnect_pending`, `retiring_authorization`,
`disconnect_draining`, `revoking`, `verifying_revocation`, and
`action_required`.

LazyCloud manages provisioning settings for connected AWS accounts. Workloads
select their CPU, memory, GPU, and pool.

## lazycloud machine

```bash
uv run lazycloud machine list
uv run lazycloud machine join [options]     # run on the machine you are joining
uv run lazycloud machine remove MACHINE_ID
```

`machine join` options:

| Option | What it does |
| --- | --- |
| `--pool <name>` | Pool to join, created if new. Default `self-hosted`. |
| `--gpu <model>` | GPU model this machine contributes. |
| `--max-cpu`, `--max-memory`, `--max-gpus` | Capacity to advertise, for example `--max-memory 32Gi`. |
| `--gpu-ids <ids>` | Comma-separated GPU device ids to expose, instead of `--max-gpus`. |
| `--background`, `--foreground` | Install the agent as a service or run it in the terminal (default). |
| `--service-manager`, `--service-name`, `--state-dir` | Service installation details. |
| `--ttl <duration>` | Lifetime of the join credential. |

Read the [host requirements](/platform/compute#your-own-machines) first.

## lazycloud domain

Custom domains are available on Team and Business plans.

```bash
uv run lazycloud domain add HOSTNAME       # prints the DNS records to create
uv run lazycloud domain status HOSTNAME
uv run lazycloud domain list
uv run lazycloud domain remove HOSTNAME
```

See [Custom domains](/platform/domains).
