The `lazycloud` command installs with the `lazycloud-client` Python package. See
[Installation](/getting-started/installation). Sign in once with
`lazycloud login`; see [Sign-in and workspaces](/platform/auth).

```text
uv run lazycloud [--json] [--debug] COMMAND [ARGS]...
```

`--json` prints one JSON document to stdout for scripting; progress goes to
stderr and errors become one JSON error document with a nonzero exit code.
Log-follow commands print newline-delimited JSON, one record per event.
Interactive commands (`shell`, `dev`, `serve`) reject `--json`. `--debug`
shows full tracebacks. `-h` or `--help` works on every command.

Human output is the default. Styling is dropped when output is redirected.

For one remote function call, use `uv run lazycloud run module:function`. It shows
progress and logs, then prints the result. Use `deploy` for an endpoint,
schedule, or a function other remote workloads need to call.

## Handler references

Use `module:object` for commands that take a `HANDLER`. Run from your project root:

- `quickstart:hello` selects `hello` in `quickstart.py`.
- `myproject.api:app` selects `app` in `myproject/api.py`.

Use dots between directory names and omit `.py`. File references such as
`quickstart.py:hello` are also supported; both forms resolve to the same handler.

The object is one decorated resource or an `App`. Deploying an `App` deploys
everything it registers; `--resource <name>` or `--resource <kind>:<name>`
selects one.

`deploy` also accepts a module without `:object`, such as
`uv run lazycloud deploy quickstart`, when it contains exactly one app. This deploys
everything registered with that app. If there are several apps, choose one with
`module:app_name`.
