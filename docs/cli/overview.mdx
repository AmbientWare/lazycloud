The `lazycloud` command installs with the `lazycloud-client` package
([Installation](/getting-started/installation)). `lazycloud login` signs in
once ([Sign-in and tokens](/platform/auth)).

```text
uv run lazycloud [--json] [--debug] COMMAND [ARGS]...
```

`--json` prints one JSON document to stdout. Progress goes to stderr, an error
is one JSON error document with a nonzero exit, and log-follow commands print
one JSON record per line. The interactive commands `shell`, `dev`, and `serve`
reject it. `--debug` shows full tracebacks. `-h` or `--help` works on every
command. Without `--json`, output is for humans, unstyled when redirected.

[Core concepts](/concepts) explains when `run`, `serve`, and
`deploy` each fit.

## Handler references

Commands that take a `HANDLER` use `module:object`, resolved from your project
root:

- `quickstart:hello` selects `hello` in `quickstart.py`.
- `myproject.api:app` selects `app` in `myproject/api.py`.

Dots separate directory names, and `.py` is omitted. A file path such as
`quickstart.py:hello` resolves to the same handler.

The object is one decorated resource or an `App`. Deploying an `App` deploys
everything it registers; `page_stats:analyze` deploys only that workload.

`deploy` also accepts a bare module, `uv run lazycloud deploy quickstart`, when
it contains exactly one app, and deploys everything registered with it. With
several apps, `module:app_name` selects one.
