## lazycloud deploy

```bash
lazycloud deploy HANDLER [options]
```

Deploys one decorated object, every resource in an `App`, or all deployable
decorated functions defined in a file or module:

```bash
lazycloud deploy quickstart.py:hello
lazycloud deploy quickstart.py
lazycloud deploy myproject.api:app
lazycloud deploy myproject.api:app --resource endpoint:predict
```

`--name` overrides the deployment name when deploying one resource, and
`--source-root <dir>` packages a different directory as the code root.

File discovery includes functions, scheduled functions, endpoints, ASGI, and
realtime handlers. Imported handlers and ordinary Python functions are excluded;
aliases deploy only once. Each handler keeps its app and deployment name.
Use an explicit `file.py:app` reference to include pods and other app resources.

When a file contains several handlers, `--name` requires selecting one with
`file.py:handler`. `--resource` requires an explicit app reference. Other overrides
must be supported by every selected handler.

Deployments run in definition order. Each success prints immediately, and a
failure stops the command without undoing completed deployments. With `--json`,
each completed deployment is one JSON line.

## lazycloud run

```bash
lazycloud run HANDLER [ARGS]... [options]
```

Calls a deployed function with the given arguments and prints the result.
An argument that parses as JSON (a number, `true` or `false`, a list, an
object) is passed as that value; anything else is passed as a string:

```bash
lazycloud run quickstart.py:hello LazyCloud
lazycloud run pipeline.py:process 42 '["a", "b"]' '{"dry_run": true}'
```

Pass a pod to run it once with a command; pass a plain function with a
`.run()` or `.remote()` method to call that.

## lazycloud serve

```bash
lazycloud serve HANDLER [--timeout <seconds>] [--resource <selector>] [options]
```

Runs an endpoint or ASGI app on LazyCloud with a temporary URL and streams
its logs. Your working directory is synced into the container as you edit;
`--sync-dir <dir>` syncs a different one. `--timeout 0`, the default, serves
until you interrupt it. `--container-port` maps the container port.

## lazycloud shell

```bash
lazycloud shell HANDLER [--sync-dir <dir>] [options]
lazycloud shell --container-id <id>
```

Opens an interactive shell in the handler's image, or attaches a shell to a
running container.

## lazycloud dev

```bash
lazycloud dev [HANDLER] [--sync <dir>] [options]
```

Opens a shell in a remote container with your working directory synced in
(`--sync ./` by default), for iterating without deploying. Without a handler
it uses the managed Python image, or `--image` or `--dockerfile` if given.

## Workload options

`deploy`, `run`, `serve`, `shell`, and `dev` accept these overrides. An option
you leave out keeps what the decorator says.

| Option | What it does |
| --- | --- |
| `--cpu <float>`, `--memory <str>` | Compute per container, for example `--memory 512Mi`. |
| `--gpu <model>`, `--gpu-count <n>` | GPU model and count. `dev` accepts `--gpu` more than once for a preference, best first. |
| `--image <ref>` | Run in a registry image. |
| `--dockerfile <path>`, `--context <dir>` | Build from a Dockerfile instead. |
| `--env KEY=VALUE` | Environment variable. Repeatable. |
| `--secret <name>` | Workspace secret to inject. Repeatable. |
| `--port <spec>` | Port to expose, as `8080` or `name=8080`. Repeatable. |
| `--keep-warm <seconds>` | Idle seconds a container stays up. |
| `--tcp`, `--no-tcp` | Raw TCP ingress instead of HTTP. |
| `--pool <name>` | Compute pool to run in. |
| `--preemptible`, `--no-preemptible` | Allow reclaimable capacity (`deploy` and `run`). |
| `--entrypoint <cmd>` | Container entrypoint override. |
