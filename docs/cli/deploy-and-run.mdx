## lazycloud deploy

```bash
uv run lazycloud deploy HANDLER [HANDLER ...] [options]
```

Deploys one workload or a whole app, chosen by
[handler reference](/cli/overview#handler-references):

```bash
uv run lazycloud deploy quickstart           # the module's only app
uv run lazycloud deploy myproject.api:app    # one app in a module
uv run lazycloud deploy quickstart:hello     # one workload
```

The deployment name comes from the workload's `name=`. `--source-root <dir>`
uploads a different directory. A failure stops the command and leaves what
already deployed. Deploying one pod or devbox prints its role and the
idle time and capacity it resolved to; an app deploy lists its devboxes.

```bash
uv run lazycloud deploy page_stats.api --diff
uv run lazycloud deploy page_stats.api -d -p
uv run lazycloud deploy page_stats.api -p
```

`--diff`, or `-d`, lists each workload as `add`, `redeploy`, `retain`, or,
with `--prune`, `remove`, and changes nothing. It imports your modules but
compares no source or configuration. `--prune`, or `-p`,
[removes workloads](/concepts/apps#remove-workloads) the code no longer
declares. Several references deploy separate apps together.

## lazycloud run

```bash
uv run lazycloud run HANDLER [ARGS]... [options]
```

Calls a function once in the cloud from your working tree, with no deploy, and
prints the result. JSON arguments become Python values; anything else stays a
string:

```bash
uv run lazycloud run quickstart:hello LazyCloud
uv run lazycloud run reports:summarize_sales '[1200, 3500, 800]'
```

Arguments are positional, so lists and objects need quotes. A pod handler
starts an instance with the given command, and a plain Python callable runs
locally. Logs go to stderr and the result to stdout. `--json` needs a
JSON-compatible result, and `--output result.pkl` saves any result to a file.

## lazycloud serve

```bash
uv run lazycloud serve HANDLER [--timeout <seconds>] [--sync-dir <dir>]
```

Runs a function, endpoint, or ASGI app as a
[live preview](/concepts#develop-test-deploy) until Ctrl+C or `--timeout`
seconds. Each edit syncs only changed files. `--sync-dir` syncs a directory
other than the current one. The Python form:

```python
from page_stats import analyze

analyze.serve(sync_dir=".")
```

Functions, endpoints, ASGI apps, and apps all have `.serve()`.

## lazycloud shell

```bash
uv run lazycloud shell HANDLER [--sync-dir <dir>] [options]
uv run lazycloud shell --container-id <id>
```

Opens a shell in the handler's image, or attaches one to a running
container.

## lazycloud ssh

```bash
uv run lazycloud ssh NAME [--app <app>] [-- <ssh options> <command>]
uv run lazycloud ssh-config [NAME...] [--app <app>] [--prune]
```

`ssh` opens a session on a [devbox](/concepts/dev-machines) or a pod with
`ssh=True`. Anything after `--` goes to `ssh`, such as
`-L 8080:localhost:8080` or a command. `ssh-config` writes host entries named
`lazycloud-<workspace>-<app>-<name>` for VS Code, Cursor, and plain `ssh`, one
per name, or one for every devbox and SSH pod in the workspace when none is
named. `--prune`, or `-p`, also removes entries for ones that stopped serving
SSH or were deleted. `--app` picks the app when several deploy the same name.
The generated config calls two hidden commands that carry the connection and
renew the login certificate.

## lazycloud devbox

```bash
uv run lazycloud devbox list [--app <app>] [--limit <n>] [--cursor <cursor>]
uv run lazycloud devbox NAME status [--app <app>]
uv run lazycloud devbox NAME start [--app <app>]
uv run lazycloud devbox NAME stop [--app <app>]
uv run lazycloud devbox NAME ssh [--app <app>] [-- <ssh options> <command>]
uv run lazycloud devbox NAME login HARNESS [--app <app>]
```

`list` returns a page of deployed devboxes and `status` shows one box's live
state and resources; both support `--json` and leave sleeping boxes asleep.
`start` waits until the box runs. `stop` stops it in any state, even mid-start
or while a failing start retries, and saves its disk. Ctrl-C while `start` or
`ssh` waits on a box it woke stops the box again. Every command accepts
`--workspace <workspace>`. See
[devboxes](/concepts/dev-machines#find-and-inspect-boxes) for listing and
selection.

`login` runs the installed agent's own browser login inside the devbox;
`HARNESS` is `codex`, `claude`, `opencode`, or `pi`. The local CLI opens your
browser and forwards the callback over SSH. It needs an interactive terminal
and rejects `--json`. See
[coding agents](/concepts/dev-machines#coding-agents) for installation,
provider selection, and credential persistence.

## lazycloud dev

```bash
uv run lazycloud dev [HANDLER] [--sync <dir>] [options]
```

Opens a shell in a remote container with your working directory synced in.
`--sync` defaults to `./`. Without a handler, `dev` uses the managed Python
image with default resources; a GPU or custom image comes from a workload
passed as the handler.
