## Install and run

<QuickstartRun />

This gives you `quickstart.py`, a README, and a project pinned to your SDK
version. `uv sync` creates the environment and `uv.lock`. Keep the lockfile
with your source so another machine can install the same dependencies.

If you belong to several workspaces, choose where to run before the next call:

```bash
uv run lazycloud workspace list
uv run lazycloud workspace use <name>
```

## Read the function

The downloaded `quickstart.py` contains:

```python
from __future__ import annotations

from lazycloud import App, Image

app = App("quickstart")
image = Image(python_version="3.12")


@app.function(name="hello", image=image, cpu=1.0, memory="256Mi")
def hello(name: str = "world") -> str:
    print(f"Greeting {name} from LazyCloud", flush=True)
    return f"hello {name}"


if __name__ == "__main__":
    print(hello.remote("LazyCloud"))
```

`Image` selects the remote Python environment. `cpu` and `memory` reserve
resources for the container. Your machine only needs the LazyCloud client.
Change these settings in the file so your next run uses the same configuration.

## Run it

```bash
uv run lazycloud run quickstart:hello LazyCloud
```

LazyCloud prepares the image, uploads your code, and runs `hello` remotely.
The command shows progress and the function's logs, then prints `hello LazyCloud`.
The first run can take longer while the image builds.

Run the command from the directory containing `quickstart.py`.
`quickstart:hello` selects `hello` from that module. `quickstart.py:hello` also works.
Arguments follow it. Change `LazyCloud` to your name and run it again.

You can also run `uv run python quickstart.py` when the SDK is installed in your Python
environment. The `.remote()` call in the file submits the same remote work.
Use `.local()` instead when you want to call the function on your own machine.

## What happens after the run

The container shuts down after its idle window. Your task's status, result,
and logs remain in the [dashboard](https://lazycloud.dev/dashboard).
Use [Tasks and logs](/concepts/tasks-and-logs) to revisit a run later or
inspect work submitted in the background.
