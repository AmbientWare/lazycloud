---
title: "Self-hosting with Helm"
description: "Install LazyCloud on Kubernetes with the bundled Helm chart."
---

The Helm chart at `deploy/charts/lazycloud` in the repository installs the
control plane, scheduler, workers, container workers, and (optionally)
PostgreSQL, Redis, and S3-compatible object storage on Kubernetes.

## Prerequisites

- A checkout of the LazyCloud repository (the chart is not yet published to a
  chart registry).
- Helm 3 and a Kubernetes cluster. Container workers run privileged and need
  `/dev/fuse` on their nodes.
- Service images pushed somewhere the cluster can pull. Build ordinary services
  from `docker/Dockerfile.control-plane`, the node agent from
  `docker/Dockerfile.agent`, container workers from `docker/Dockerfile.worker`,
  and the JuiceFS gateway from `docker/Dockerfile.storage-gateway`. Set the
  corresponding image values to your registry.

## Required configuration

The chart refuses to render without `controlPlane.publicHttpUrl` — the URL
your users will reach the control plane on:

```yaml
# my-values.yaml
controlPlane:
  publicHttpUrl: https://lazycloud.example.com
```

`deploy/charts/lazycloud/values.local.yaml` is a working single-node profile for
local clusters (kind, minikube, k3s) that sets the public URL to the
documented port-forward, `http://127.0.0.1:8000`.

## Install

```bash
helm install lazycloud deploy/charts/lazycloud \
  --namespace lazycloud-system \
  --create-namespace \
  --values deploy/charts/lazycloud/values.local.yaml
```

Validate a configuration without a cluster:

```bash
helm lint deploy/charts/lazycloud --values deploy/charts/lazycloud/values.local.yaml
helm template lazycloud deploy/charts/lazycloud \
  --namespace lazycloud-system \
  --values deploy/charts/lazycloud/values.local.yaml
```

The database bootstrap hook creates an empty database on install. It also runs
before a Helm upgrade and proceeds only when the database already matches the
single current schema baseline; stale or unknown revisions fail closed.

## Reach the control plane

With the local values profile, port-forward the service:

```bash
kubectl -n lazycloud-system port-forward svc/lazycloud 8000:9000
lazycloud login --endpoint http://127.0.0.1:8000
```

For production, terminate at your ingress or load balancer and set
`controlPlane.publicHttpUrl` to that URL.

## Key values

| Value | Purpose |
| --- | --- |
| `controlPlane.publicHttpUrl` | Required public URL of the control plane. |
| `image`, `scheduler.image`, `databaseBootstrap.image`, `cache.image` | Control-plane service images. |
| `administratorBootstrap.image`, `containerWorkers.workerTokenBootstrap.image` | Bootstrap images. |
| `containerWorkers.image` | Privileged container-worker image. |
| `juicefs.gateway.image` | Minimal image used by JuiceFS format, S3 gateway, and WebDAV. |
| `service.type` / `service.port` | Control plane service (default ClusterIP:9000). |
| `database.secretRef`, `redis.secretRef` | Bring your own PostgreSQL/Redis via secret references. |
| `objectStore.*` | Bundled S3-compatible store, or point at your own with `endpointUrl` and credentials. |
| `scheduler.*`, worker sections | Scheduler and worker sizing, autoscaling, and compute reclaim settings. |

`deploy/charts/lazycloud/values.schema.json` validates the full value surface;
`helm lint` reports violations.

## Upgrades

```bash
helm upgrade lazycloud deploy/charts/lazycloud \
  --namespace lazycloud-system \
  --values my-values.yaml
```

Image-only upgrades are supported while the schema baseline is unchanged. This
repository is predeployment and does not carry release-to-release database
migrations. When the baseline changes, recreate only a release and database you
have positively identified as disposable, then install the chart fresh. Do not
delete a namespace, PVC, or external database whose ownership or persistence
requirements are uncertain. Forward-only migration guidance will replace this
policy when the first persistent production installation is declared.
