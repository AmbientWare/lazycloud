---
title: "OpenAI-compatible LLM service"
description: "Run a small instruction model behind an authenticated vLLM pod on one GPU."
---

This example deploys the official vLLM OpenAI server as a pod. It serves
`Qwen/Qwen2.5-1.5B-Instruct` on one NVIDIA L4 and keeps downloaded model
files in a volume, so a replacement container reuses the cache instead of
downloading again.

The source is `examples/openai_compatible_llm/app.py` in the LazyCloud
repository.

## Prerequisites

- Sign in with `lazycloud login`.
- Create an access token in the dashboard for calling the service directly,
  and export it:

```bash
export LAZYCLOUD_TOKEN="<access-token>"
```

The model is public, so no Hugging Face token is needed.

## The pod

The pod runs the pinned `vllm/vllm-openai:v0.23.0` image. vLLM, PyTorch, and
CUDA stay in that image; nothing is installed locally.

```python
from lazycloud import App, GpuType, Image, Volume

app = App("openai_compatible_llm")
model_cache = Volume("vllm-model-cache", "/root/.cache/huggingface")

server = app.pod(
    name="openai-server",
    image=Image.from_registry("vllm/vllm-openai:v0.23.0"),
    command=[
        "vllm", "serve",
        "--host", "0.0.0.0",
        "--port", "8000",
        "--model", "Qwen/Qwen2.5-1.5B-Instruct",
        "--served-model-name", "qwen-1.5b",
        "--download-dir", "/root/.cache/huggingface",
        "--max-model-len", "8192",
        "--gpu-memory-utilization", "0.90",
    ],
    ports={"http": 8000},
    env={"HF_HOME": "/root/.cache/huggingface"},
    cpu=4.0,
    memory="16Gi",
    gpu=GpuType.L4,
    gpu_count=1,
    volumes=[model_cache],
    authorized=True,
)
```

`authorized=True` makes LazyCloud require a bearer token before a request
reaches vLLM. The example sets no separate vLLM API key.

## Deploy

```bash
lazycloud volume create vllm-model-cache
lazycloud deploy examples.openai_compatible_llm.app:app --resource pod:openai-server
```

The first start downloads the model, so it takes a while. Copy the pod URL
from the deploy output, without a trailing slash:

```bash
export VLLM_URL="<pod-url>"
```

Wait for the health check to pass before sending requests:

```bash
curl --fail --show-error "$VLLM_URL/health" \
  -H "Authorization: Bearer $LAZYCLOUD_TOKEN"
```

A request without the header is rejected before it reaches vLLM.

## Use it

```bash
curl --fail --show-error "$VLLM_URL/v1/models" \
  -H "Authorization: Bearer $LAZYCLOUD_TOKEN"
```

```bash
curl --fail --show-error "$VLLM_URL/v1/chat/completions" \
  -H "Authorization: Bearer $LAZYCLOUD_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "qwen-1.5b",
    "messages": [
      {"role": "user", "content": "Explain durable model caches in one sentence."}
    ],
    "max_tokens": 80,
    "temperature": 0.2
  }'
```

The response follows the OpenAI chat-completions schema.

## Inspect

```bash
lazycloud deployment list --app openai_compatible_llm
lazycloud container list
lazycloud logs --deployment openai-server --follow --show-timestamp
lazycloud volume list
```

To see the cache in use, stop the running container and watch the
replacement's logs. It skips the download:

```bash
lazycloud container stop <container-id>
lazycloud logs --deployment openai-server --follow --show-timestamp
```

## Cost and licensing

The pod holds an L4 while it runs, so it costs GPU, CPU, and memory time
until you stop or delete the deployment. Check the Usage page before leaving
it up. The 1.5B model fits on one L4; concurrency and context length still
affect GPU memory.

- vLLM publishes the server image and its
  [Docker instructions](https://docs.vllm.ai/en/latest/deployment/docker/).
- `Qwen/Qwen2.5-1.5B-Instruct` is on its
  [Hugging Face model card](https://huggingface.co/Qwen/Qwen2.5-1.5B-Instruct)
  under the Apache 2.0 license. Read the card before using the weights in a
  product.

## Clean up

Delete the deployment first so nothing is still using the volume:

```bash
lazycloud deployment delete openai-server
lazycloud volume delete vllm-model-cache --yes
unset VLLM_URL
```

Keep the volume if you want the next deployment to reuse the download. It is
billed while it exists.
