title: "Document processing with FastAPI"
description: "A FastAPI upload service with background OCR on a function, polling over durable tasks, and results in a volume."
---

This example is a complete FastAPI application. It accepts a raw upload, runs
OCR on a function in the background, lets the client poll the task through a
signed job token, and keeps files in a volume. The included browser UI uses
the same HTTP routes shown below.

The source is `examples/document_processing/` in the LazyCloud repository:
resource declarations, the API, the worker, validation and token helpers, and
the static UI.

## How it works

The public ASGI app and the private OCR function share one volume.

1. `PUT /api/documents/{filename}` streams a PDF, JPEG, or PNG to a temporary
   file, with a 10 MiB limit.
2. The API submits the document id and validated suffix to the deployed
   `ocr-worker` function.
3. The response carries an HMAC-signed job token that expires after 24 hours.
   The browser keeps it in memory and sends it in `X-Job-Token`; it never
   appears in a URL.
4. Status comes from the task record. The API only accepts a verified token,
   so a client cannot read an arbitrary task.
5. The worker renders PDFs with Poppler, runs Tesseract, writes JSON to the
   volume, and removes the raw upload whether OCR succeeded or failed.
6. The client deletes the result after reading it.

There is no in-memory job table and no workspace credential in the browser.

## Prerequisites

Sign in with `lazycloud login`, have `curl` and a PDF, JPEG, or PNG at hand,
and create the volume and a fresh signing secret. Do not reuse an API key:

```bash
export DOCUMENT_JOB_TOKEN_SECRET="$(python -c 'import secrets; print(secrets.token_urlsafe(48))')"
lazycloud secret create DOCUMENT_JOB_TOKEN_SECRET "$DOCUMENT_JOB_TOKEN_SECRET"
unset DOCUMENT_JOB_TOKEN_SECRET
lazycloud volume create document-processing-data
```

Only the ASGI workload receives the secret. The OCR worker does not.

## The resources

The image pins FastAPI and installs Tesseract and Poppler. Your machine needs
neither.

```python
from lazycloud import App, Image, Volume

app = App("document_processing")
data = Volume("document-processing-data", "/document-processing")
image = (
    Image(python_version="3.12")
    .add_python_packages(["fastapi==0.139.2"])
    .add_commands([
        "apt-get update && DEBIAN_FRONTEND=noninteractive apt-get install -y "
        "--no-install-recommends poppler-utils tesseract-ocr && "
        "rm -rf /var/lib/apt/lists/*"
    ])
)


@app.function(name="ocr-worker", image=image, timeout_seconds=600, retries=0, volumes=[data])
def ocr_document(document_id: str, suffix: str) -> dict[str, object]:
    ...


web = app.asgi(
    name="document-api",
    image=image,
    route="/",
    authorized=False,
    secrets=["DOCUMENT_JOB_TOKEN_SECRET"],
    volumes=[data],
)(api)
```

The worker calls `subprocess.run` with argument lists, caps PDFs at 20 pages,
times out each command, and caps results at 200,000 characters. A filename is
never evaluated as a shell command.

## Deploy

```bash
lazycloud deploy examples.document_processing.app:app
```

Copy the `document-api` URL from the deploy output, without a trailing slash:

```bash
export DOCUMENT_API_URL="<document-api-url>"
curl --fail --show-error "$DOCUMENT_API_URL/health"
```

Opening `$DOCUMENT_API_URL` in a browser loads the upload UI.

## Upload a document

The body is the raw file, so no multipart parser is needed:

```bash
curl --fail --show-error \
  -X PUT "$DOCUMENT_API_URL/api/documents/sample.pdf" \
  -H "Content-Type: application/pdf" \
  --data-binary @sample.pdf
```

Keep the returned `job_token` in a shell variable rather than printing it.
The commands below use `<job-token>` as a placeholder.

## Poll and read the result

```bash
curl --fail --show-error "$DOCUMENT_API_URL/api/jobs/status" \
  -H "X-Job-Token: <job-token>"

curl --fail --show-error "$DOCUMENT_API_URL/api/jobs/result" \
  -H "X-Job-Token: <job-token>"
```

Status is `pending`, `running`, `retry`, or a terminal task state. The result
route returns `409` until the task is complete.

The job token is a bearer capability. Anyone holding it can read or delete
that job until it expires, so do not log it, put it in a query string, or
store it in browser local storage.

## Delete a result

```bash
curl --fail --show-error \
  -X DELETE "$DOCUMENT_API_URL/api/jobs" \
  -H "X-Job-Token: <job-token>"
```

Deletion returns `409` while the task is still running. The worker removes raw
uploads itself; result files stay in the volume until deleted, so add a
retention job if clients may abandon results.

## Inspect

```bash
lazycloud deployment list --app document_processing
lazycloud task list --limit 20
lazycloud logs --deployment ocr-worker --follow --show-timestamp
lazycloud ls document-processing-data/results
```

## What this does not protect

`document-api` sets `authorized=False` so the browser UI can upload and poll
without a LazyCloud token. Job tokens give per-job access; they are not user
authentication. Before exposing this pattern to the internet, put it behind
your own authentication and tenant checks, add edge rate and body limits,
malware scanning, retention, and monitoring, and rotate
`DOCUMENT_JOB_TOKEN_SECRET` on a schedule. Rotation invalidates outstanding
tokens.

## Clean up

```bash
lazycloud deployment delete document-api
lazycloud deployment delete ocr-worker
lazycloud volume delete document-processing-data --yes
lazycloud secret delete DOCUMENT_JOB_TOKEN_SECRET
unset DOCUMENT_API_URL
```
