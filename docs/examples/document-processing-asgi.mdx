Upload a PDF, JPEG, or PNG and read its text in a browser. This example runs
FastAPI as an HTTP service and Tesseract in a separate background function.
Files pass between them through a volume.

Source is in `examples/document_processing/`.

<ExampleSetup />

## Prepare the app

Install FastAPI in your local example environment so the CLI can import the
application. Tesseract and Poppler install only in the remote image.

```bash
uv pip install fastapi==0.139.2
```

Create a signing secret and the volume:

```bash
DOCUMENT_JOB_TOKEN_SECRET="$(python -c 'import secrets; print(secrets.token_urlsafe(48))')"
lazycloud secret create DOCUMENT_JOB_TOKEN_SECRET "$DOCUMENT_JOB_TOKEN_SECRET"
unset DOCUMENT_JOB_TOKEN_SECRET
lazycloud volume create document-processing-data
```

The signing secret protects access to individual results. Only the HTTP
service receives it.

<Warning>
  This example's upload URL is public. Anyone with the URL can submit work
  that uses your compute. Use test documents, stop the app when finished, and
  add user authentication and upload rate limits before offering it to users.
</Warning>

## Deploy and upload

```bash
lazycloud deploy examples.document_processing.app:app
```

Open the `document-api` URL from the deploy output. Select a document in the
upload form. The page submits it, shows job progress, and displays the extracted
text. PDFs can contain up to 20 pages; uploads are limited to 10 MiB and text
results to 200,000 characters.

The worker removes the raw upload after processing, including on failure.
Click Delete result in the browser when you no longer need it. Results from abandoned jobs
remain in the volume until you delete them.

## Call the API from a script

Set the URL without a trailing slash. These commands need curl and jq:

```bash
export DOCUMENT_API_URL="<document-api-url>"
JOB_TOKEN="$(
  curl --fail --show-error \
    -X PUT "$DOCUMENT_API_URL/api/documents/sample.pdf" \
    -H "Content-Type: application/pdf" \
    --data-binary @sample.pdf |
  jq -er '.job_token'
)"
```

This uploads a local `sample.pdf` and saves the returned job token without
printing it. Read the status:

```bash
curl --fail --show-error "$DOCUMENT_API_URL/api/jobs/status" \
  -H "X-Job-Token: $JOB_TOKEN"
```

Once status is `complete`, fetch the text:

```bash
curl --fail --show-error "$DOCUMENT_API_URL/api/jobs/result" \
  -H "X-Job-Token: $JOB_TOKEN"
```

The result route returns HTTP 409 while the task is unfinished. If the task
fails, inspect its error before retrying the upload. The token expires after
24 hours and permits reading or deleting that job. Keep it out of logs and URLs.

Delete the result when your script has saved it:

```bash
curl --fail --show-error -X DELETE "$DOCUMENT_API_URL/api/jobs" \
  -H "X-Job-Token: $JOB_TOKEN"
unset JOB_TOKEN
```

Deletion returns HTTP 409 if work is still running.

## Diagnose a failed upload or job

For an HTTP error, inspect `lazycloud logs --deployment document-api -n 100`.
For OCR failures, use:

```bash
lazycloud task list --app document_processing --limit 20
lazycloud task logs <task-id>
```

The API and worker definitions live in `app.py` and `worker.py`.
Change resource sizes and upload limits there and in `resources.py` when
adapting the app. Add a retention job for abandoned results.
Rotating `DOCUMENT_JOB_TOKEN_SECRET` invalidates outstanding job tokens.

## Clean up

Delete the two deployments to stop accepting work:

```bash
lazycloud deployment delete document-api
lazycloud deployment delete ocr-worker
```

If you created the volume and secret for this example, download any results
you need before removing them:

```bash
lazycloud volume delete document-processing-data
lazycloud secret delete DOCUMENT_JOB_TOKEN_SECRET
unset DOCUMENT_API_URL
```
