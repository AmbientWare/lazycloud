This example trains a small detector in one GPU function and loads the
checkpoint in a second one. A `yolo-artifacts` volume keeps checkpoints,
metrics, and annotated images after both containers exit.

The default run trains on Ultralytics' eight-image COCO8 dataset for one
epoch. Use it to check training, checkpoint storage, and prediction before
spending GPU time on your own dataset.

The source is `examples/yolo_training/app.py` in the LazyCloud repository.

<ExampleSetup />

You need access to an L4 and a positive credit balance. Training and prediction
both use GPU compute. Check [Ultralytics licensing](https://www.ultralytics.com/license)
before adapting the example for commercial use.

## Prepare storage

Both functions use the pinned Ultralytics image in
`examples/yolo_training/app.py`. Training writes a checkpoint and metrics;
prediction reads that checkpoint from the same volume. The code rejects paths
outside the volume and refuses to overwrite an existing run directory.


```bash
lazycloud volume create yolo-artifacts
```

Torch, CUDA, and Ultralytics stay inside the image; nothing is installed
locally.

## Train

With no arguments the function uses `coco8.yaml`, YOLO26n, and one epoch:

```bash
lazycloud run examples.yolo_training.app:train_yolo
```

The command shows training logs and returns checkpoint and metrics paths.
Download the metrics CSV:

```bash
lazycloud cp lazycloud://yolo-artifacts/training/coco8-smoke/results.csv ./results.csv
```

Compute is charged while the container runs, including startup and its idle
window. For this one-epoch run,
startup and the model download often take longer than training. Check the
Usage page before raising `epochs`, image size, or dataset size.

## Predict

The prediction function loads the saved `best.pt` and, by default, runs it on
Ultralytics' public `bus.jpg`:

```bash
lazycloud run examples.yolo_training.app:predict_yolo
lazycloud cp lazycloud://yolo-artifacts/predictions/bus-prediction/bus.jpg ./bus-prediction.jpg
```

Open `bus-prediction.jpg` to see the detected objects. The one-epoch run
checks the workflow; evaluate accuracy on your own data before using the
predictions in a product.

## Use your own data

Upload the dataset and its Ultralytics YAML to the volume. Paths inside the
YAML must point at files under `/artifacts` too.

```bash
lazycloud cp ./datasets/my-detector lazycloud://yolo-artifacts/datasets/my-detector
lazycloud run examples.yolo_training.app:train_yolo custom-run 50 datasets/my-detector/data.yaml
```

To predict on an uploaded image, pass its volume-relative path as the third
argument. The first two name the training run and the prediction run:

```bash
lazycloud cp ./sample.jpg lazycloud://yolo-artifacts/inputs/sample.jpg
lazycloud run examples.yolo_training.app:predict_yolo custom-run sample-prediction inputs/sample.jpg
```

Run names cannot be reused. Pick a new training name for another trial and
use that same name for prediction. This preserves your earlier checkpoint.

If training fails, use `lazycloud task list --app yolo_training` and inspect
that task's logs. Check the dataset path before retrying with a new name.

## Clean up

The function containers shut down after their idle window. Keep the volume
while you still need the checkpoints. Download important files before deleting them.

Remove runs you no longer need:

```bash
lazycloud rm yolo-artifacts/training/coco8-smoke
lazycloud rm yolo-artifacts/predictions/bus-prediction
```

Or delete the whole volume:

```bash
lazycloud volume delete yolo-artifacts
```

<Warning>
  Deleting the volume deletes every checkpoint in it. Download what you want
  to keep first.
</Warning>
