---
title: "Train a YOLO object detector"
description: "Train YOLO26n on an L4 GPU, persist its checkpoint, and run prediction from a separate Function."
---

This example trains a small object detector in one GPU Function and loads the
resulting checkpoint in a separate prediction Function. A durable
`yolo-artifacts` Volume keeps checkpoints, metrics, and annotated images after
either container exits.

The default smoke run uses Ultralytics' eight-image COCO8 dataset for one epoch.
It is deliberately small enough to verify the complete workflow; it is not a
meaningful accuracy benchmark.

## Define the workloads

The complete implementation lives in `examples/yolo_training/app.py`. The two
Functions share the same pinned official Ultralytics image and artifact Volume:

```python
from lazycloud import App, GpuType, Image, Volume

image = Image.from_registry("ultralytics/ultralytics:8.4.101")
artifacts = Volume("yolo-artifacts", "/artifacts")
app = App("yolo_training")


@app.function(
    name="train-yolo",
    image=image,
    gpu=GpuType.L4,
    gpu_count=1,
    volumes=[artifacts],
    timeout_seconds=3600,
)
def train_yolo(run_name: str = "coco8-smoke", epochs: int = 1):
    ...


@app.function(
    name="predict-yolo",
    image=image,
    gpu=GpuType.L4,
    gpu_count=1,
    volumes=[artifacts],
)
def predict_yolo(training_run: str = "coco8-smoke"):
    ...
```

The implementation invokes the `yolo` executable with an argument vector, not
a shell command. It accepts bounded run names and resolves every caller-provided
dataset or image path beneath `/artifacts`; absolute paths, parent traversal,
empty segments, and symlink escapes are rejected.

## Create the Volume and deploy

Run these commands from the repository root. Replace `default` if you use a
different workspace.

```bash
uv run lazycloud volume create yolo-artifacts --workspace default
uv run lazycloud deploy examples.yolo_training.app:app --workspace default
uv run lazycloud deployment list --app yolo_training --workspace default
```

The deployment builds no local ML environment. Torch, CUDA, and Ultralytics stay
inside the pinned `ultralytics/ultralytics:8.4.101` runtime image.

## Train on COCO8

Invoke the training Function without arguments to use `coco8.yaml`, YOLO26n,
and one epoch:

```bash
uv run lazycloud run examples.yolo_training.app:train_yolo --workspace default
```

The returned JSON identifies the durable checkpoint and metrics file. Inspect
the run and its Task logs:

```bash
uv run lazycloud task list --limit 10 --workspace default
uv run lazycloud task logs <training-task-id> --workspace default
uv run lazycloud ls yolo-artifacts/training/coco8-smoke --workspace default
uv run lazycloud cp lazycloud://yolo-artifacts/training/coco8-smoke/results.csv ./results.csv --workspace default
```

Training uses one L4 only while the Function is running. Your compute provider's
GPU rate, image transfer, and model download determine the actual cost; for this
one-epoch smoke, startup frequently takes longer than training. Check Usage and
your provider's pricing before increasing `epochs`, image size, or dataset size.

## Run prediction

The prediction Function loads the persisted `best.pt` and, by default, runs it
against Ultralytics' public `bus.jpg` sample:

```bash
uv run lazycloud run examples.yolo_training.app:predict_yolo --workspace default
uv run lazycloud task logs <prediction-task-id> --workspace default
uv run lazycloud ls yolo-artifacts/predictions/bus-prediction --workspace default
```

Download the returned annotated-image path with `lazycloud cp`, for example:

```bash
uv run lazycloud cp lazycloud://yolo-artifacts/predictions/bus-prediction/bus.jpg ./bus-prediction.jpg --workspace default
```

## Use your own data

Put your dataset and Ultralytics dataset YAML in the Volume. Paths in the YAML
should refer to files that are also available below `/artifacts`.

```bash
uv run lazycloud cp ./datasets/my-detector lazycloud://yolo-artifacts/datasets/my-detector --workspace default
uv run lazycloud run examples.yolo_training.app:train_yolo custom-run 50 datasets/my-detector/data.yaml --workspace default
```

To predict from an uploaded image, pass its Volume-relative path as the third
argument. The first two arguments select the training and prediction runs:

```bash
uv run lazycloud cp ./sample.jpg lazycloud://yolo-artifacts/inputs/sample.jpg --workspace default
uv run lazycloud run examples.yolo_training.app:predict_yolo custom-run sample-prediction inputs/sample.jpg --workspace default
```

Run names are immutable in this example. Choose a new name for another run, or
remove the old run directory explicitly before retrying. This prevents a typo or
retry from silently overwriting a checkpoint.

## Retention and cleanup

Deleting deployments stops future invocations but intentionally retains the
Volume and its trained artifacts:

```bash
uv run lazycloud deployment delete train-yolo --workspace default
uv run lazycloud deployment delete predict-yolo --workspace default
```

Remove individual runs when you no longer need them:

```bash
uv run lazycloud rm yolo-artifacts/training/coco8-smoke --workspace default
uv run lazycloud rm yolo-artifacts/predictions/bus-prediction --workspace default
```

Or permanently delete the complete example Volume and every artifact in it:

```bash
uv run lazycloud volume delete yolo-artifacts --yes --workspace default
```

<Warning>
  Volume deletion is destructive. Download any checkpoints you want to retain
  before running the final command.
</Warning>

## Models, datasets, and licenses

- The runtime is the official versioned Ultralytics image `8.4.101`; the model
  is the lightweight `yolo26n.pt` checkpoint. Review the
  [Ultralytics licensing options](https://www.ultralytics.com/license) before
  distributing a model or integrating it into a commercial product.
- [COCO8](https://docs.ultralytics.com/datasets/detect/coco8/) contains the first
  eight COCO 2017 images and their labels. Review COCO's dataset terms and each
  source image's license before reusing the images outside this smoke test.
- Custom data remains your responsibility: verify its collection rights,
  annotation license, privacy requirements, and permitted model use.

<Note>
  This repository verifies the import, workload specification, path controls,
  and subprocess contract without downloading ML dependencies. A real one-epoch
  train-and-predict acceptance still requires authorized L4 capacity and incurs
  provider cost; no CPU or mocked execution is presented as GPU acceptance.
</Note>
