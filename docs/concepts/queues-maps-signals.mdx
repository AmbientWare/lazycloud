---
title: "Queues, maps, and signals"
description: "Shared state for coordinating work across containers."
---

Use a queue to pass work items between processes, a map for temporary shared
values, and a signal for notifications. Objects with the same name in the
same workspace share data. Sign in before running these Python examples.

## Queue

A FIFO queue of JSON-serializable values:

```python
from lazycloud import Queue

q = Queue("work-items")

q.put({"path": "a.wav"})
print(len(q))
print(q.peek())
item = q.pop()
print(item)
```

`pop()` removes the item. Your consumer must decide what to do if processing
fails afterward. For work that needs task results and retries, submit a
[function](/concepts/functions#submit-work-in-the-background) instead.
`QueueDepthAutoscaler` scales a function's pending calls, not this named queue.

## Map

A key/value map with the `MutableMapping` interface:

```python
from lazycloud import Map

state = Map("pipeline-state")

state["cursor"] = 42
state.get("cursor")
state.set("cursor", 43, ttl=3600)   # per-key TTL in seconds
"cursor" in state
list(state.keys())
len(state)
del state["cursor"]
```

Keys expire after seven days unless `set(..., ttl=...)` says otherwise. Seven
days is also the maximum.

## Send a signal

A signal is a named flag one container sets and another checks. Use it to
request a cache reload. The API is experimental and may change between releases.

```python
from lazycloud.abstractions.experimental import Signal

reload_flag = Signal("reload-models")

# Producer
reload_flag.set(ttl=600)    # 600 seconds is the default

# Consumer: check once
response = reload_flag.monitor_once()

reload_flag.clear()
```

For a long-running consumer, pass a `handler` and call
`start_monitoring(poll_interval_seconds=1.0)`. Call `stop_monitoring()` when
your consumer shuts down.

## Remove example state

When you no longer need the example data, `q.delete()` removes the queue and
its remaining items, and `state.delete()` removes the map and all its keys.
