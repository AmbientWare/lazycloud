---
title: "Queues, maps, and signals"
description: "Shared state for coordinating work across containers."
---

These objects share state between workloads and your local process. They are
addressed by name: two objects with the same name in the same workspace share
the same data. Inspect them under Storage in the dashboard.

## Queue

A FIFO queue of JSON-serializable values:

```python
from lazycloud import Queue

q = Queue("work-items")

q.put({"path": "a.wav"})
len(q)          # 1
q.empty()       # False
q.peek()        # read the head without removing it
item = q.pop()
q.delete()      # remove the queue and its contents
```

Pair a queue with a function whose `autoscaler` is a
[`QueueDepthAutoscaler`](/concepts/functions#warm-containers-and-concurrency)
to scale consumers with backlog.

## Map

A key/value map with the `MutableMapping` interface:

```python
from lazycloud import Map

state = Map("pipeline-state")

state["cursor"] = 42
state.get("cursor")
state.set("cursor", 43, ttl=3600)   # per-key TTL in seconds
"cursor" in state
list(state.keys())
len(state)
del state["cursor"]
state.delete()                      # remove the whole map
```

Keys expire after seven days unless `set(..., ttl=...)` says otherwise. Seven
days is also the maximum.

## Signal (experimental)

A named flag one container sets and another reacts to. Use it for cache
invalidation, reload triggers, and similar notifications.

```python
from lazycloud.abstractions.experimental import Signal

reload_flag = Signal("reload-models")

# Producer
reload_flag.set(ttl=600)    # 600 seconds is the default

# Consumer: check once
response = reload_flag.monitor_once()

# Or poll in a background thread
signal = Signal("reload-models", handler=lambda: print("reloading"))
signal.start_monitoring(poll_interval_seconds=1.0)
signal.stop_monitoring()

reload_flag.clear()
```

<Note>
  `Signal` is experimental. Its interface may change between releases.
</Note>
