---
title: "Schedules"
description: "Run a function on a schedule with a cron expression, an alias, or an interval."
---

A schedule is a property of a function, not a separate workload. Pass `cron`
to `@app.function` and each run is an ordinary invocation.

```python
from lazycloud import App, Image

app = App("maintenance")
image = Image(python_version="3.12")


@app.function(cron="0 3 * * *", name="nightly_cleanup", image=image)
def cleanup() -> dict[str, str]:
    return {"status": "clean"}
```

```bash
lazycloud deploy maintenance.py:cleanup
```

## Schedule syntax

Three forms work:

- A five-field cron expression: `"*/15 * * * *"`, `"0 3 * * 1"`.
- An alias: `"@hourly"`, `"@daily"`, `"@midnight"`, `"@weekly"`,
  `"@monthly"`, `"@yearly"`, `"@annually"`.
- An interval: `"every 5m"` (up to 59m), `"every 2h"` (up to 23h),
  `"every 3d"` (up to 31d).

Schedules run in UTC. An invalid expression is rejected at deploy time.

## Behavior

A scheduled function takes every option a function does: resources, image,
timeout, retries, secrets, volumes, hooks, and pool. Each run is a durable
task, so a failing run retries per its retry settings and shows up in
[task history](/concepts/tasks-and-logs) and the dashboard.

You can still call it directly. `.local()` runs it in your process, and
`.remote()` or `.spawn()` trigger a run outside the schedule.

`keep_warm` defaults to `0` for a scheduled function, since the next run is
usually further away than a warm window is worth. Set it if runs are close
together.

Deploying again replaces the schedule; one fires per resource. Removing `cron`
and deploying again removes the schedule while keeping the function deployed
and callable. To stop the runs entirely, stop or delete the deployment:

```bash
lazycloud deployment list --app maintenance
lazycloud deployment stop nightly_cleanup
lazycloud deployment delete nightly_cleanup
```
