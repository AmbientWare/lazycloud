A volume keeps files after your container stops. Declare it in Python and
attach it to each workload that needs it. LazyCloud creates the volume the
first time a container mounts it and reuses it on later runs.

## Declare and use a volume

Save this as `reports.py`:

```python
import json
from pathlib import Path

from lazycloud import App, Volume

app = App("reports")
reports = Volume("sales-reports", "/reports")


@app.function(volumes=[reports])
def save_report(amounts_cents: list[int]) -> dict[str, int]:
    summary = {"sales": len(amounts_cents), "total_cents": sum(amounts_cents)}
    Path("/reports/latest.json").write_text(json.dumps(summary))
    return summary


if __name__ == "__main__":
    print(save_report.remote([1200, 3500, 800]))
    reports.get("latest.json", "latest.json")
```

Run it with the SDK installed and signed in:

```bash
uv run python reports.py
```

The function returns three sales totaling 5500 cents, and the script downloads
`latest.json` to your current directory. You don't create the volume first.
Running the script again replaces the file.

`Volume(...)` declares the name and mount path and makes no API call on its
own. `volumes=[reports]` tells LazyCloud to mount it. Within a workspace, a
name always refers to the same stored files, even from another app. Use a
different name for separate data.

Changing the mount path changes where a container sees the files. Changing the
volume name selects another volume and leaves the old data where it is.
Removing a mount or deleting a deployment also leaves stored files intact.

LazyCloud stores a volume where its workspace lives. See
[Compute](/platform/compute). Storage bills per GiB-month. See
[Plans and limits](/platform/plans).

## Upload inputs before the first run

If a workload needs files before it starts, create or reuse its declared
volume from your local setup script, then upload them:

```python
from lazycloud import Volume

models = Volume("models", "/models")
models.create()
models.put("weights.pt", "weights.pt")
```

This needs a local `weights.pt`. Attach the same `models` object to your
function with `volumes=[models]` to read `/models/weights.pt` remotely.
`create()` returns the existing volume when its name already exists.
`get_or_create()` performs the same operation and returns a boolean.

Keep provisioning and uploads in an explicit setup function or an
`if __name__ == "__main__":` block. Importing a workload module should only
declare resources, never upload data or change stored values.

## Read and write from Python

Inside a container, a mounted volume is a directory. From your local script,
use the `Volume` object:

```python
from reports import reports

print(reports.read_text("latest.json"))
print(reports.list())
print(reports.stat("latest.json"))
reports.get("latest.json", "downloaded-report.json")
```

`put(source, destination)` uploads a local file or directory.
`write_text()` and `write_bytes()` write content directly.
`read_text()` and `read_bytes()` retrieve it.
`list_path()` returns entries with size and time, and `move()` renames a path.

For multi-gigabyte uploads, `presigned_url(...)`,
`create_multipart_upload(...)`, `complete_multipart_upload(...)`, and
`abort_multipart_upload(...)` let you upload in parts.

## Share files between containers

Every container that mounts a volume sees the same files, so parallel calls
and long-lived services can share data through it. A volume is object storage
presented as a directory, which leads to these rules:

- Other containers see a file once the writer closes it, and the file is
  durable from then on. Write whole files and close them. Another container
  may not see a partly written file.
- When two containers write the same path, the last close wins and nothing
  merges. Give each call its own output path, such as
  `/reports/{task_id}.json`, and have a final step combine them.
- There are no file locks. Coordinate through a [queue or map](/concepts/queues-maps)
  when containers must take turns.
- Appending to a large file or seeking inside one rewrites the object. Keep
  logs and append-only data in many small files or send them elsewhere.
- The first read of a large file downloads it. Later reads on the same
  machine come from a local cache. Volumes suit large, read-mostly data such
  as model weights.

Download weights once and let every container reuse them:

```python
from pathlib import Path

from lazycloud import App, Volume

app = App("inference")
models = Volume("models", "/models")
WEIGHTS = Path("/models/encoder.safetensors")


def ensure_weights() -> None:
    if WEIGHTS.exists():
        return
    partial = WEIGHTS.with_suffix(".part")
    download_weights(partial)   # your download code
    partial.rename(WEIGHTS)


@app.function(gpu="l4", volumes=[models], on_start=ensure_weights, concurrency=4, in_process=True)
def encode(text: str) -> list[float]:
    ...
```

The `on_start` hook runs before the container takes calls. Downloading to a
`.part` path and renaming means a container that starts mid-download sees
either no file or a complete one. Two containers that start at the same moment
may both download. Because of the rename, that costs a wasted download, not a
corrupt file.

## Mount an existing cloud bucket

`CloudBucket` mounts an S3-compatible bucket you own. Reads and writes go
straight to the bucket, and LazyCloud copies nothing into its own storage.

```python
from pathlib import Path

from lazycloud import App, CloudBucket, CloudBucketConfig

app = App("etl")
bucket = CloudBucket(
    "my-data-bucket",
    "/data",
    CloudBucketConfig(
        access_key="MY_BUCKET_ACCESS_KEY",
        secret_key="MY_BUCKET_SECRET_KEY",
        region="us-east-1",
    ),
)


@app.function(volumes=[bucket])
def read_text_file(key: str) -> str:
    return (Path("/data") / key).read_text()
```

`access_key` and `secret_key` name [workspace secrets](/concepts/secrets).
Provision their values before running the workload. Set both names or neither.
With neither, the mount uses the compute's credentials, such as the instance role
on your [connected AWS account](/platform/compute).

`CloudBucketConfig` also accepts `bucket` when the bucket name differs from the
mount name, `prefix` to mount part of the bucket, `endpoint` for another
S3-compatible store, `force_path_style`, and `read_only`.

The bucket must already exist. Declaring a mount never creates it. See
[parallel Parquet processing](/examples/parallel-parquet-s3) for a complete
workflow.

## Delete stored data

`reports.remove("latest.json")` deletes one file, and `reports.delete()` deletes
the volume and every file in it. Stop workloads that mount a volume before
deleting it, because their next run creates an empty volume with the same name.
To inspect or copy files from a terminal, use the
[file commands](/cli/storage#files).
