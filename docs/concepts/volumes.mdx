## Volumes

A `Volume` is a durable filesystem owned by the workspace. Mount it into any
workload at a path you choose. Use it for model weights, datasets, and
anything that should outlive a container.

```python
from pathlib import Path

from lazycloud import App, Volume

app = App("training")
models = Volume("models", "/models")


@app.function(volumes=[models])
def load(name: str) -> int:
    return len((Path("/models") / name).read_bytes())
```

Create it from the CLI or Python:

```bash
lazycloud volume create models
lazycloud volume list
lazycloud volume delete models
```

```python
models.get_or_create()   # idempotent; .create() and .delete() also exist
```

Volume storage is billed per GiB-month. See [Plans and limits](/platform/plans).

## Move files

Inside a container, a mounted volume is a directory. From outside, the `Volume`
object reads and writes it:

```python
models.put("weights.pt", "llama/weights.pt")     # upload
models.get("llama/weights.pt", "weights.pt")     # download
models.list("llama")                              # names under a prefix
models.list_path("llama")                         # entries with size and time
models.stat("llama/weights.pt")
models.move("llama/weights.pt", "archive/weights.pt")
models.remove("archive/weights.pt")

models.write_text("notes.txt", "hello")
models.read_text("notes.txt")
models.write_bytes("blob.bin", b"\x00")
models.read_bytes("blob.bin")
```

The CLI does the same with `lazycloud://<volume>/<path>` paths. The scheme is
optional except on the source of a download, where it marks the path as
remote:

```bash
lazycloud ls models/llama
lazycloud cp weights.pt lazycloud://models/llama/weights.pt
lazycloud cp lazycloud://models/llama/weights.pt ./weights.pt
lazycloud mv models/llama/weights.pt models/archive/weights.pt
lazycloud rm models/archive/weights.pt
```

For multi-gigabyte uploads, `presigned_url(...)`,
`create_multipart_upload(...)`, `complete_multipart_upload(...)`, and
`abort_multipart_upload(...)` let you upload in parts.

## Cloud buckets

`CloudBucket` mounts an S3-compatible bucket you own into workloads. Reads and
writes go to the bucket in place; nothing is copied into LazyCloud storage.

```python
from pathlib import Path

from lazycloud import App, CloudBucket, CloudBucketConfig

app = App("etl")

bucket = CloudBucket(
    "my-data-bucket",
    "/data",
    CloudBucketConfig(
        access_key="MY_BUCKET_ACCESS_KEY",
        secret_key="MY_BUCKET_SECRET_KEY",
        region="us-east-1",
    ),
)


@app.function(volumes=[bucket])
def process(key: str) -> str:
    return (Path("/data") / key).read_text()
```

`access_key` and `secret_key` are the names of [workspace secrets](/concepts/secrets)
holding your credentials, never the values. Set both or neither. With neither,
the mount uses the credentials of the compute it runs on, for example the
instance role on your [connected AWS account](/platform/compute).

`CloudBucketConfig` also takes `bucket` when the bucket name differs from the
mount name, `prefix` to mount only part of the bucket, `endpoint` for a
non-AWS S3-compatible store, `force_path_style` for stores that need
path-style addressing, and `read_only`. The bucket must already exist; a
mount never creates one.
