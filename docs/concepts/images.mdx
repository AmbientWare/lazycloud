---
title: "Images"
description: "Build a workload's container from Python: packages, system tools, a project's lockfile, or an existing registry image."
---

Anything a workload needs beyond the standard library goes in its `Image`,
along with the Python version it runs. LazyCloud builds the image in the cloud,
so nothing installs on your machine.

## Install remote dependencies

```python
from lazycloud import App, Image

app = App("audio")

image = (
    Image(python_version="3.12")
    .add_commands(["apt-get update && apt-get install -y ffmpeg"])
)


@app.function(image=image)
def ffmpeg_version() -> str:
    import subprocess

    return subprocess.check_output(["ffmpeg", "-version"], text=True).splitlines()[0]
```

Save this as `audio.py` and run `uv run lazycloud run audio:ffmpeg_version`.
The result is the ffmpeg version inside the cloud container, and your machine
does not need ffmpeg.
`.add_python_packages(["httpx"])` installs a Python dependency.

LazyCloud caches images by content. Pinned dependency versions make builds
reproducible.

`Image()` with no arguments is the managed Python 3.12 image. Python 3.10
through 3.14 are available. You can also pin a patch release, such as `3.12.11`.

## Create an image from a project

A factory selects Python and installs the project's dependencies:

```python
from lazycloud import Image

image = Image.from_uv(".")
```

The path is the project directory. The build reads its `pyproject.toml`,
lockfile, and `.python-version`, plus any local dependencies they name,
honoring each dependency's `.lazycloudignore`. Your own code is not part of the image. It reaches the
container through source sync, so editing it never rebuilds the image.
Changing a dependency does. The build uploads nothing outside this directory,
so workspace members and relative path dependencies belong inside it. Build
backends run in the image, not on your laptop.

The build does not install the root project. Code under `src/` is still
importable at runtime.

### uv

```python
image = Image.from_uv(".", extras=["gpu"], groups=["inference"])
```

Requires `pyproject.toml` and `uv.lock`. The build checks that the lockfile
matches the project and installs its locked dependencies. It excludes default
dependency groups, including `dev`, unless `groups` names them.
Workspace members and path sources install without editable mode. The root
project is not installed.

### Poetry

```python
image = Image.from_poetry(".", extras=["gpu"], groups=["inference"])
```

Requires `pyproject.toml` and `poetry.lock`. The build validates the lockfile and
uses Poetry to install the main dependencies and selected groups and extras.
The root project is never installed, whatever Poetry's package mode says.

### Standard pyproject.toml

```python
image = Image.from_pyproject(".", extras=["gpu"], groups=["inference"])
```

Uses standard `[project]` metadata and `[dependency-groups]` and needs no
lockfile. The build resolves dependencies itself and does not treat a uv or
Poetry lockfile as a guarantee. `Image.from_uv` and `Image.from_poetry` install
locked dependencies.

The build installs only dependencies. It reads workspace members and
`[tool.uv.sources]` path entries from `pyproject.toml` and uploads them with it.

### Micromamba

```yaml environment.yml
channels:
  - conda-forge
dependencies:
  - python=3.12
  - numpy
  - pip:
      - httpx==0.28.1
```

```python
image = Image.from_micromamba("environment.yml")
```

The environment file supplies Python requirements, channels, Conda packages,
and pip dependencies. An environment YAML is not a lockfile, so the build
resolves unpinned packages. The build includes relative files from the YAML's
directory.

### Python selection

An explicit `python_version` overrides the project's interpreter pin:

```python
image = Image.from_uv(".", python_version="3.12.11")
```

Otherwise the image uses the project's pin, which is `.python-version` for
Python projects and the `python=` entry for Micromamba. Without a pin, it uses
Python 3.12 when compatible. An unsupported pin fails instead of switching
versions.

Factories return an ordinary image that you can extend:

```python
image = Image.from_uv(".").add_commands([
    "apt-get update && apt-get install -y ffmpeg"
])
```

All four factories also accept `base_image`, `base_image_creds`, and
`architecture`, with the same values as the constructor:

```python
image = Image.from_uv(
    ".", base_image="nvidia/cuda:12.3.1-runtime-ubuntu22.04"
)
```

These factories configure the remote environment. The CLI still imports your
handler module locally, so its top-level imports must resolve on your machine.
Running `uv run lazycloud run main:handler` from the project environment
handles that, and remote-only imports can live inside the handler.

## Constructor

```python
Image(
    python_version="3.12",         # supported minor or exact patch release
    python_packages=["httpx"],     # package specs, or a path to requirements.txt
    commands=["python --version"], # shell commands run during the build
    base_image=None,               # start from a registry image instead
    base_image_creds=None,         # registry credentials, see below
    env_vars=None,                 # environment variables baked into the image
)
```

## Builder methods

Each returns the image, so they chain.

- `add_python_packages(packages)` installs packages. Pass a list of specs or a
  path to a `requirements.txt`.
- `add_commands(commands)` runs shell commands during the build.
- `add_local_path(pattern="*")` includes matching local files in the build
  context.
- `add_micromamba_packages(packages, channels=[...])` adds packages to an image
  created with `from_micromamba()`.
- `with_envs(env_vars, clear=False)` sets environment variables from a
  mapping, `"KEY=value"` strings, or a sequence of them.
- `with_secrets(secrets)` makes workspace secrets available during the build.
- `with_docker()` installs Docker so containers using the image can run their
  own daemon.
- `build_with_gpu(hint)` runs the build on a GPU worker of the given model.

## Start from an existing image

```python
gpu_image = Image.from_registry(
    "nvidia/cuda:12.3.1-runtime-ubuntu22.04", python_version="3.11"
)
custom_image = Image.from_dockerfile("./Dockerfile", context_dir=".")
```

`Image.from_id(image_id)` reuses a sandbox filesystem snapshot, given the ID
the snapshot returned.

### Private registries

Credentials are environment variable names read at deploy time, never values
in code:

```python
image = Image.from_registry(
    "ghcr.io/acme/models:latest",
    credentials=["GHCR_USERNAME", "GHCR_PASSWORD"],
)
```
