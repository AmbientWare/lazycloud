## Endpoints

`@app.endpoint` gives a Python callable an HTTP route. Arguments come from the
request body and the return value is serialized as the response.

```python
from lazycloud import App, Image

app = App("api_demo")
image = Image(python_version="3.12")


@app.endpoint(name="predict", route="/predict", methods=["POST"], image=image)
def predict(value: int = 7) -> dict[str, int]:
    return {"input": value, "prediction": value + 1}
```

`route` defaults to `/` and `methods` to `GET` and `POST`. Endpoints default
to `cpu=1.0`, `memory="128Mi"`, `timeout_seconds=180`, `retries=0`, one worker
with `concurrency=1`, `keep_warm=180`, `max_pending_tasks=100`, and
`authorized=True`.

### Calling an endpoint

`lazycloud deploy` prints the endpoint's URL. Send a bearer token for the
workspace unless the endpoint sets `authorized=False`:

```bash
curl -X POST "<endpoint-url>" \
  -H "Authorization: Bearer $LAZYCLOUD_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"value": 41}'
```

The decorated object is a typed client too:

```python
response = predict.request(41)                      # served preview if one is running, else deployed
response = predict.target("deployed").request(41)
print(response.status_code, response.json())
```

`target()` takes `"auto"`, `"served"`, or `"deployed"`, plus
`deployment_name` and `deployment_version` to pin one deployment.
`predict.local(41)` calls the plain function in your process.

### Scaling

`workers` is the number of containers. `concurrency` is requests per
container. `keep_warm` is how long an idle worker stays up before scaling to
zero. `max_pending_tasks` bounds the request queue; requests past it are
refused rather than queued.

For autoscaling on backlog:

```python
from lazycloud import QueueDepthAutoscaler


@app.endpoint(
    name="infer",
    autoscaler=QueueDepthAutoscaler(min_containers=0, max_containers=8, tasks_per_container=2),
)
def infer(prompt: str) -> str: ...
```

`checkpoint_enabled=True` snapshots a warmed worker so replacements restore
from it instead of cold-starting.

## ASGI applications

`@app.asgi` deploys any ASGI callable. A FastAPI or Starlette instance is one,
so apply the decorator to it directly:

```python
from fastapi import FastAPI

api = FastAPI()
service = app.asgi(name="service", route="/")(api)
```

A raw `scope, receive, send` callable works the same way:

```python
@app.asgi(name="ping")
async def ping(scope, receive, send) -> None:
    await send({"type": "http.response.start", "status": 200, "headers": []})
    await send({"type": "http.response.body", "body": b"ok"})
```

ASGI apps take the endpoint options with two renamed: `concurrent_requests`
and `keep_warm_seconds`. `name` defaults to `"asgi"`.

Call a deployed ASGI app with a full request:

```python
response = service.request(method="GET", path="/health", target="deployed")
```

`request()` accepts `method`, `path`, `json`, `data`, `headers`, `params`,
and the same `target`, `deployment_name`, and `deployment_version` options as
endpoints.

## Realtime handlers

`@app.realtime` turns a function into a WebSocket handler. Each incoming
message calls the handler with the message; the return value is sent back, and
an iterable return sends each item.

```python
@app.realtime(name="echo")
def echo(message: str) -> str:
    return message
```

Realtime handlers take the ASGI options and deploy, serve, and scale the same
way. `name` defaults to `"realtime"`.

## Preview before deploying

`lazycloud serve` runs an endpoint or ASGI app on LazyCloud with a temporary
URL and streams logs, syncing your working directory into the container as you
edit:

```bash
lazycloud serve api_demo.py:predict
```

## Custom domains

On the Team plan, `domain="app.acme.com"` on an endpoint, ASGI app, or
realtime handler serves it from a hostname you own. See
[Custom domains](/platform/domains).
