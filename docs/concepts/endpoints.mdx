## Endpoints

Use `@app.endpoint` when another application needs to call your Python over
HTTP. Save this as `api_demo.py`. It counts words in a JSON request:

```python
from lazycloud import App, Image

app = App("api_demo")
image = Image(python_version="3.12")


@app.endpoint(name="count_words", route="/word-count", methods=["POST"], image=image)
def count_words(text: str) -> dict[str, int]:
    return {"words": len(text.split())}
```

`route` defaults to `/` and `methods` to `GET` and `POST`. Endpoints default
to `cpu=1.0`, `memory="128Mi"`, `timeout_seconds=180`, `retries=0`,
`keep_warm=180`, and `authorized=True`, and serve one request at a time in one
container until you change that; see [Scaling](#scaling).

### Calling an endpoint

Deploy it:

```bash
uv run lazycloud deploy api_demo:count_words
```

The command prints the endpoint's URL. Send a bearer token for the
workspace unless the endpoint sets `authorized=False`:

```bash
curl --fail --show-error "<endpoint-url>" \
  -H "Authorization: Bearer $LAZYCLOUD_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"text": "Run Python on LazyCloud"}'
```

The response is `{"words": 4}`. Set `LAZYCLOUD_TOKEN` to an access token from
Settings, then Tokens. See [the endpoint walkthrough](/getting-started/first-endpoint)
for the complete sign-in and request steps. `authorized=False` allows anyone
who has the URL to call the endpoint.

The decorated object is a typed client too:

```python
from api_demo import count_words

response = count_words.target("deployed").request("Run Python on LazyCloud")
print(response.status_code, response.json())
```

`target()` takes `"auto"`, `"served"`, or `"deployed"`, plus
`deployment_name` and `deployment_version` to pin one deployment.
`count_words.request(...)` uses a served preview when one exists, otherwise the
deployment. `count_words.local("some text")` calls the function in your process.

### Scaling

Three numbers set an endpoint's capacity. `workers` is the number of server
processes in one container. `concurrency` is how many requests each process
handles at once, so a container accepts `workers * concurrency` requests in
flight. `autoscaler` is how many containers the endpoint may run:

```python
from lazycloud import QueueDepthAutoscaler


@app.endpoint(
    name="word-count-scaled",
    cpu=2,
    workers=2,
    concurrency=8,
    autoscaler=QueueDepthAutoscaler(min_containers=0, max_containers=8, tasks_per_container=16),
)
def count_words_scaled(text: str) -> dict[str, int]:
    return {"words": len(text.split())}
```

This endpoint handles 16 requests per container and adds a container for every
16 requests in flight, up to 8. Set `tasks_per_container` to match
`workers * concurrency`; when you omit `autoscaler` that happens for you, with
`max_containers=1`.

Workers are separate processes, so `on_start` runs in each one and a model
loaded there is loaded once per worker. For a GPU model keep `workers=1` and
raise `concurrency`.

`keep_warm` is how long a container with no requests stays up, 180 seconds by
default. `min_containers` keeps containers up regardless, so the first request
after a quiet period does not pay for a start. `max_pending_tasks`, 100 by
default, caps requests in flight; past it the endpoint answers `429`. A
request that finds every slot busy waits up to `timeout_seconds` for one.

`checkpoint_enabled=True` snapshots a warmed worker so replacements restore
from it instead of running startup again.

[Scaling and concurrency](/concepts/scaling) has sizing examples for a GPU
model behind HTTP and for a CPU API with steady traffic.

## ASGI applications

Use `@app.asgi` for an existing FastAPI or Starlette application with several
routes. Save this complete example as `web_app.py`. Install FastAPI locally
with `uv add fastapi` so the CLI can import the file:

```python
from fastapi import FastAPI
from lazycloud import App, Image

app = App("web_app")
api = FastAPI()


@api.get("/health")
def health() -> dict[str, str]:
    return {"status": "ok"}


service = app.asgi(
    name="service",
    image=Image().add_python_packages(["fastapi"]),
)(api)
```

```bash
uv run lazycloud deploy web_app:service
```

ASGI apps take the endpoint options with two renamed: `concurrent_requests`
and `keep_warm_seconds`. `name` defaults to `"asgi"`. The defaults are
`workers=1`, `concurrent_requests=1`, `keep_warm_seconds=180`,
`timeout_seconds=180`, and `max_pending_tasks=100`. An async FastAPI app can
take a high `concurrent_requests` in one worker; a blocking one needs more
`workers` instead:

```python
service = app.asgi(
    name="service",
    cpu=2,
    workers=2,
    concurrent_requests=32,
    image=Image().add_python_packages(["fastapi"]),
)(api)
```

Call a deployed ASGI app with a full request:

```python
response = service.request(method="GET", path="/health", target="deployed")
print(response.json())
```

`request()` accepts `method`, `path`, `json`, `data`, `headers`, `params`,
and the same `target`, `deployment_name`, and `deployment_version` options as
endpoints.

## Realtime handlers

`@app.realtime` turns a function into a WebSocket handler. Each incoming
message calls the handler with the message; the return value is sent back, and
an iterable return sends each item.

```python
@app.realtime(name="echo")
def echo(message: str) -> str:
    return message
```

Realtime handlers take the ASGI options and deploy, serve, and scale the same
way. `name` defaults to `"realtime"`.

## Preview before deploying

`uv run lazycloud serve` runs an endpoint or ASGI app on LazyCloud with a temporary
URL and streams logs, syncing your working directory into the container as you
edit:

```bash
uv run lazycloud serve api_demo:count_words
```

While the preview runs, `count_words.request(...)` from this machine goes to it
instead of the deployment. [Local, preview, deploy](/getting-started/workflow)
explains the target rules.

## Custom domains

On Team and Business plans, `domain="app.example.com"` on an endpoint, ASGI app, or
realtime handler serves it from a hostname you own. See
[Custom domains](/platform/domains).

## Shared options

To stop an endpoint, use `uv run lazycloud deployment stop <name>`. Warm containers
incur compute charges while they remain running.

Endpoints, ASGI apps, and realtime handlers also accept `env`, `secrets`,
`volumes`, an `on_start` hook that runs in each worker process as it starts,
`task_policy`, and the options below.
