description: "Serve HTTP from a typed Python function, a FastAPI or Starlette app, or a WebSocket handler."
---

Three workloads serve traffic over the network. Pick by what you already have:

| You have | Use |
| --- | --- |
| One Python function that should answer HTTP requests | `@app.endpoint` |
| A FastAPI or Starlette app with several routes | `app.asgi(...)` |
| A handler that answers WebSocket messages | `@app.realtime` |

All three get a stable URL when deployed, require a workspace bearer token
unless you set `authorized=False`, and preview with
[`lazycloud serve`](/concepts/workflow#live-preview).

## Endpoints

Save this as `api_demo.py`:

```python
from lazycloud import App

app = App("api_demo")


@app.endpoint(name="count_words", route="/word-count", methods=["POST"])
def count_words(text: str) -> dict[str, int]:
    return {"words": len(text.split())}
```

LazyCloud maps the JSON request body to the function's arguments and returns
the result as JSON. `route` defaults to `/` and `methods` to `GET` and `POST`.

Deploy it, then call the printed URL with an
[access token](/platform/auth#ci-and-scripts):

```bash
uv run lazycloud deploy api_demo:count_words
curl --fail --show-error "<endpoint-url>" \
  -H "Authorization: Bearer $LAZYCLOUD_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"text": "Run Python on LazyCloud"}'
```

The response is `{"words": 4}`. With `authorized=False`, anyone who has the URL
can call it.

From Python, the decorated function is a client that uses your
`lazycloud login` credentials:

```python
from api_demo import count_words

response = count_words.request("Run Python on LazyCloud")
print(response.status_code, response.json())
```

`request()` goes to a running preview if there is one and to the deployment
otherwise. `count_words.target("deployed")` or `target("served")` picks one
explicitly, and `deployment_name` and `deployment_version` pin a deployment.

### Capacity

An endpoint runs one server process that handles one request at a time, in one
container. Three settings raise that:

```python
from lazycloud import QueueDepthAutoscaler


@app.endpoint(
    name="word-count-scaled",
    cpu=2,
    workers=2,
    concurrency=8,
    autoscaler=QueueDepthAutoscaler(max_containers=8, tasks_per_container=16),
)
def count_words_scaled(text: str) -> dict[str, int]:
    return {"words": len(text.split())}
```

Each container runs `workers` processes that each take `concurrency` requests,
so this one handles 16 at once and adds a container for every 16 in flight, up
to 8. Past `max_pending_tasks` (100 by default) the endpoint answers `429`.
[Scaling and concurrency](/concepts/scaling) explains how to choose these values
and has sizing patterns for a GPU model and a CPU API.

`checkpoint_enabled=True` snapshots a warmed worker so replacement containers
restore from it instead of running `on_start` again.

## ASGI applications

Wrap an existing FastAPI or Starlette app with `app.asgi(...)`. Save this as
`web_app.py`, and run `uv add fastapi` so the CLI can import it locally:

```python
from fastapi import FastAPI
from lazycloud import App, Image

app = App("web_app")
api = FastAPI()


@api.get("/health")
def health() -> dict[str, str]:
    return {"status": "ok"}


service = app.asgi(
    name="service",
    image=Image().add_python_packages(["fastapi"]),
)(api)
```

```bash
uv run lazycloud deploy web_app:service
```

ASGI apps take the endpoint options, with `concurrent_requests` in place of
`concurrency` and `keep_warm_seconds` in place of `keep_warm`. `name` defaults
to `"asgi"`. An async app can take a high `concurrent_requests` in one worker;
a blocking one needs more `workers`.

Call a route from Python with a full request:

```python
from web_app import service

response = service.request(method="GET", path="/health", target="deployed")
print(response.json())
```

`request()` accepts `method`, `path`, `json`, `data`, `headers`, and `params`,
plus the same target options as endpoints. An
[exported client package](/concepts/apps#call-deployed-workloads-from-other-projects)
gives each route a typed method from the app's OpenAPI schema.

## Realtime handlers

`@app.realtime` turns a function into a WebSocket handler. Each incoming
message calls the handler; the return value is sent back, and an iterable
return sends each item as its own message.

```python
@app.realtime(name="echo")
def echo(message: str) -> str:
    return message
```

Realtime handlers take the ASGI options and deploy, preview, and scale the same
way. `name` defaults to `"realtime"`.

## Domains and shutdown

On Team and Business plans, `domain="api.example.com"` serves any of the three
from a hostname you own; see [Custom domains](/platform/domains).

Warm containers are billed while they run. Stop a deployment you no longer
need with `uv run lazycloud deployment stop <name>`.

Defaults and every option are in [Resources and options](/concepts/resources).
