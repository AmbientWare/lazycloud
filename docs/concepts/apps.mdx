---
title: "Apps"
description: "An App groups the workloads you deploy together under one name."
---

An `App` is the unit you deploy. Every workload registers under an app slug,
and the slug is how the dashboard and CLI refer to it.

```python
from lazycloud import App

app = App("billing")
```

A slug starts with a lowercase letter and contains only lowercase letters,
digits, and underscores, up to 63 characters: `"billing"`, `"reporting_api"`.

## Register workloads

```python
@app.function(...)      # a remote function
@app.endpoint(...)      # an HTTP endpoint
@app.asgi(...)          # a FastAPI, Starlette, or raw ASGI app
@app.realtime(...)      # a WebSocket-style handler
web = app.pod(...)      # a long-running container command
box = app.sandbox(...)  # an on-demand container
```

Names must be unique per kind within an app. Registering the same name twice
raises an error.

## Deploy

Deploy everything the app registers:

```bash
lazycloud deploy billing_app.py:app
```

Or from Python:

```python
app.deploy()
```

Deploy one resource with a selector. Pass its name, or `"kind:name"` when the
name exists in more than one kind:

```bash
lazycloud deploy billing_app.py:app --resource endpoint:api
```

```python
app.deploy(resource="endpoint:api")
```

Sandboxes are created on demand and are not deployed.

## Preview

`lazycloud serve` runs one function, endpoint, or ASGI app on LazyCloud with a temporary
URL and live logs. When an app has more than one, pick one:

```bash
lazycloud serve billing_app.py:app --resource endpoint:api
```

## Export a typed Python package

```bash
lazycloud app export billing
```

This writes `lazycloud_clients/billing`. Import a deployed function or endpoint
by its resource name and call its typed methods. Function methods include
`remote()` and `async_remote()`; endpoint methods include `request()` and
`async_request()`. Sign in with `lazycloud login` before calling them. Generated
files contain deployment references and schemas, never credentials.

Function and endpoint types come from their deployed callable contracts. ASGI
route methods come from OpenAPI 3, discovered at `/openapi.json`. Choose another
path or supply a JSON file when needed:

```bash
lazycloud app export billing --openapi-path api=/schema/openapi.json
lazycloud app export billing --openapi api=./openapi.json
```

ASGI methods use the schema's operation IDs and include async equivalents.
They support JSON bodies and path, query, and header parameters. Unsupported
parameter locations or body formats fail generation with an explanation.
An ASGI app without a schema keeps `request()` and `async_request()` for raw
HTTP calls; the command reports that its route types are unavailable.

Export again after deploying contract changes. Packages include functions,
endpoints, and ASGI apps. Pods and sandboxes are excluded.

## Manage a deployed app

```bash
lazycloud app list
lazycloud app show billing
lazycloud app pause billing     # stop every workload in the app
lazycloud app resume billing
lazycloud app delete billing
```

The same actions are on the app's page in the dashboard.
