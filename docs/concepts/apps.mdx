---
title: "Apps"
description: "Group related functions, APIs, and containers so you can deploy and manage them together."
---

An `App` groups workloads under a name in your workspace. Use one app for
resources you want to deploy, pause, or inspect together.

Keep resource configuration in Python with the app: images, CPU and GPU
requests, volume mounts, secret names, schedules, and scaling settings.
Run or deploy those definitions from the CLI or Python. Use CLI overrides for
one-off experiments; put lasting changes back in the source.

## Define an app

Save this as `text_tools.py`:

```python
from lazycloud import App

app = App("text_tools")


@app.function()
def count_words(text: str) -> int:
    return len(text.split())


@app.endpoint(name="count", methods=["POST"])
def count(text: str) -> dict[str, int]:
    return {"words": count_words.local(text)}
```

App names start with a lowercase letter and contain lowercase letters,
digits, or underscores, up to 63 characters. Workload names must be unique
within each kind in the app.

## Deploy together

```bash
uv run lazycloud deploy text_tools
```

This deploys both workloads. A module name selects its only app.
Use `text_tools:app` to select the app explicitly when a module has several.

`@app.function`, `@app.endpoint`, `@app.asgi`, `@app.realtime`, and
`app.pod(...)` register deployable workloads. Sandboxes created with
`app.sandbox(...)` run on demand and are not started by a deploy.

Mounted [volumes](/concepts/volumes) are created on first use and reused by
name in the workspace. [Secret values](/concepts/secrets) need explicit
provisioning. Removing a resource from the code does not delete its stored data;
review and remove unused resources separately.

## Deploy or preview one workload

```bash
uv run lazycloud deploy text_tools:app --resource endpoint:count
```

A selector is the resource name, or `kind:name` if the name is shared by
several kinds. You can also pass the decorated object directly:

```bash
uv run lazycloud serve text_tools:count
```

The preview prints a temporary URL and logs. Ctrl+C ends it.

From Python, use `app.deploy()` or `app.deploy(resource="endpoint:count")`.

## Export a typed Python package

```bash
uv run lazycloud app export text_tools
```

This writes `lazycloud_clients/text_tools`. Import a deployed function or endpoint
by its resource name and call its typed methods. Function methods include
`remote()` and `async_remote()`; endpoint methods include `request()` and
`async_request()`. Sign in with `lazycloud login` before calling them. Generated
files contain deployment references and schemas, never credentials.

Function and endpoint types come from their deployed callable contracts. ASGI
route methods come from OpenAPI 3, discovered at `/openapi.json`. Choose another
path or supply a JSON file when needed. For example, for the `service` ASGI
app from the [ASGI guide](/concepts/endpoints#asgi-applications):

```bash
uv run lazycloud app export web_app --openapi-path service=/schema/openapi.json
uv run lazycloud app export web_app --openapi service=./openapi.json
```

ASGI methods are named after the schema's operation IDs. Routes the generator
cannot type fail with an explanation; an ASGI app without a schema keeps
`request()` and `async_request()` for raw HTTP calls.

Export again after deploying contract changes. Packages include functions,
endpoints, and ASGI apps. Pods and sandboxes are excluded.

## Manage the app

```bash
uv run lazycloud app show text_tools
```

To stop its workloads while keeping their definitions:

```bash
uv run lazycloud app pause text_tools
```

Use `uv run lazycloud app resume text_tools` to resume. When you no longer need
the app, `uv run lazycloud app delete text_tools` removes it. Check separately for
[stored files](/concepts/volumes) you want to retain or delete.
