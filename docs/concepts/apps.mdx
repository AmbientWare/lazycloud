---
title: "Apps"
description: "An App groups the workloads you deploy together under one name."
---

An `App` is the unit you deploy. Every workload registers under an app slug,
and the slug is how the dashboard, the CLI, and generated clients refer to it.

```python
from lazycloud import App

app = App("billing")
```

A slug starts with a lowercase letter and contains only lowercase letters,
digits, and underscores, up to 63 characters: `"billing"`, `"reporting_api"`.

## Register workloads

```python
@app.function(...)      # a remote function
@app.endpoint(...)      # an HTTP endpoint
@app.asgi(...)          # a FastAPI, Starlette, or raw ASGI app
@app.realtime(...)      # a WebSocket-style handler
web = app.pod(...)      # a long-running container command
box = app.sandbox(...)  # an on-demand container
```

Names must be unique per kind within an app. Registering the same name twice
raises an error.

## Deploy

Deploy everything the app registers:

```bash
lazycloud deploy billing_app.py:app
```

Or from Python:

```python
app.deploy()
```

Deploy one resource with a selector. Pass its name, or `"kind:name"` when the
name exists in more than one kind:

```bash
lazycloud deploy billing_app.py:app --resource endpoint:api
```

```python
app.deploy(resource="endpoint:api")
```

Sandboxes are created on demand and are not deployed.

## Preview

`lazycloud serve` runs one endpoint or ASGI app on LazyCloud with a temporary
URL and live logs. When an app has more than one, pick one:

```bash
lazycloud serve billing_app.py:app --resource endpoint:api
```

## Manage a deployed app

```bash
lazycloud app list
lazycloud app show billing
lazycloud app pause billing     # stop every workload in the app
lazycloud app resume billing
lazycloud app delete billing
```

The same actions are on the app's page in the dashboard.
