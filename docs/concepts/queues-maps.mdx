description: "Shared state for coordinating work across containers."

Use a queue to pass work items between processes and a map for temporary shared
values. Objects with the same name in the same workspace share data.
Sign in before running these Python examples.

## Queue

A FIFO queue of JSON-serializable values:

```python
from lazycloud import Queue

q = Queue("work-items")

q.put({"path": "a.wav"})
print(len(q))
print(q.peek())
item = q.pop()
print(item)
```

`pop()` removes the item. Your consumer must decide what to do if processing
fails afterward. For work that needs task results and retries, submit a
[function](/concepts/functions#submit-work-in-the-background) instead.
`QueueDepthAutoscaler` scales a function's pending calls, not this named queue.

## Map

A key/value map with the `MutableMapping` interface:

```python
from lazycloud import Map

state = Map("pipeline-state")

state["cursor"] = 42
state.get("cursor")
state.set("cursor", 43, ttl=3600)   # per-key TTL in seconds
"cursor" in state
list(state.keys())
len(state)
del state["cursor"]
```

Keys expire after seven days unless `set(..., ttl=...)` says otherwise. Seven
days is the maximum timed expiry. Use `ttl=0` to keep a key until you delete it.

## Edit from the dashboard

Open **Storage**, then **Queues** or **Maps**. Keep repeatable setup in your
Python code; use the dashboard to inspect data or make an ad hoc correction.

For a map, select a key to view or edit its value and expiry. Saving fails if a
workload changed the key meanwhile; reload and try again. Binary Python values
can be inspected and deleted but not edited.

**Add key** creates a key without overwriting an existing one. To create a
map, choose **New map** and enter its name and first key/value.

For a queue, **Add message** appends JSON to the end. Viewing the head message
does not remove it. **Remove next message** consumes the next message without
running it and shows what was removed. Another consumer can take the previewed
message before you confirm, so the removed message may be different.
**New queue** creates a named queue with its first message.

Deleting a queue removes its remaining messages. Deleting a map removes all
its keys. Both actions require confirmation and cannot be undone. Running code
can recreate a deleted collection with its next write.

## Remove example state

When you no longer need the example data, `q.delete()` removes the queue and
its remaining items, and `state.delete()` removes the map and all its keys.
