title: "Queues and maps"
description: "Shared state for coordinating work across containers."
---

A queue passes work items between processes, and a map holds temporary shared
values. Within a workspace, a queue or map with the same name refers to the
same data.

## Queue

`Queue` is a FIFO queue of JSON-serializable values:

```python
from lazycloud import Queue

q = Queue("work-items")

q.put({"path": "a.wav"})
print(len(q))
print(q.peek())
item = q.pop()
print(item)
```

`pop()` removes and returns the next item, or `None` when the queue is empty.
Each item goes to exactly one caller, however many containers pop at once. If
processing fails after the pop, your consumer decides what happens to the item.
For work that needs task results and retries, submit a
[function](/concepts/functions#submit-work-in-the-background) instead.
`QueueDepthAutoscaler` scales on a function's pending calls, not on this named
queue.

## Coordinate containers

`.map()` fits when every input is known up front. A queue fits work discovered
as you go, producers and consumers that run at different times, or a handful of
long-lived workers draining a stream of small items without a task per item. A
map records progress those workers can share:

```python
from lazycloud import App, Map, Queue, QueueDepthAutoscaler

app = App("crawler")
frontier = Queue("crawl-frontier")
seen = Map("crawl-seen")


@app.function(
    cpu=1,
    memory="512Mi",
    timeout_seconds=3600,
    retries=0,
    autoscaler=QueueDepthAutoscaler(max_containers=8),
)
def crawl_worker() -> int:
    handled = 0
    while (url := frontier.pop()) is not None:
        if url in seen:
            continue
        seen.set(url, True, ttl=86400)
        for link in fetch_links(url):   # your fetch code
            frontier.put(link)
        handled += 1
    return handled


if __name__ == "__main__":
    frontier.put("https://example.com/")
    calls = crawl_worker.spawn_map([() for _ in range(8)])
    print(sum(call.get() for call in calls))
```

Eight workers on eight containers pop from one queue and stop when it is
empty. Without the autoscaler they would run one after another. The map's `in`
check and `set` are separate calls, so two workers can both pass the check for
the same URL and fetch it twice. A crawler can tolerate that. A payment cannot.
An item that must be handled exactly once needs an idempotent handler, or a
function call, which has a task record and retries.

The queue has no acknowledgement, so a worker that crashes after a pop loses
the item. Small, re-creatable items limit the loss. Otherwise a worker can
write each item to a map before working on it, and a sweeper can requeue stale
entries.

## Map

`Map` is a key/value store with the `MutableMapping` interface:

```python
from lazycloud import Map

state = Map("pipeline-state")

state["cursor"] = 42
state.get("cursor")
state.set("cursor", 43, ttl=3600)   # per-key TTL in seconds
"cursor" in state
list(state.keys())
len(state)
del state["cursor"]
```

Keys expire after seven days unless `set(..., ttl=...)` says otherwise. Seven
days is the maximum timed expiry. `ttl=0` keeps a key until you delete it.

## Remove example state

`q.delete()` removes the queue and its remaining items. `state.delete()`
removes the map and all its keys.
