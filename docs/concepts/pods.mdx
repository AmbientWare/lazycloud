---
title: "Pods"
description: "Run a long-lived container command under your app."
---

A pod runs a container command: a web server, a worker process, a model
server. It is not tied to a Python callable, so it can run any image.

```python
from lazycloud import App, Image

app = App("tools")

web = app.pod(
    name="web",
    image=Image(python_version="3.12"),
    command=["python", "-m", "http.server", "8080"],
    ports={"http": 8080},
    cpu=0.5,
    memory="256Mi",
)
```

Pods default to `cpu=1.0`, `memory="128Mi"`, `keep_warm=600`, and
`authorized=False`.

## Deploy it

Deploying a pod keeps it running under a deployment. The deploy output prints
its URL.

```bash
lazycloud deploy tools.py:app --resource pod:web
```

Manage it through the deployment, from Python with `web.scale(containers)`,
`web.pause()`, `web.resume()`, and `web.delete()`, or from the CLI:

```bash
lazycloud deployment list --app tools
lazycloud deployment scale web --containers 2
lazycloud deployment stop web
```

## Or create an instance on demand

A pod can also run once without a deployment:

```python
instance = web.create()                                   # runs the configured command
print(instance.container_id, instance.url)

instance = web.run("python", "-m", "http.server", "9090")  # a different command
instance.terminate()
```

Both return a `PodInstance` with `container_id`, `url`, `timeout_seconds`,
`expires_at`, and `terminate()`. The instance lives for `keep_warm` seconds
unless you pass `timeout_seconds`.

## Options

`command` and `ports` describe what runs and what it listens on. `ports` maps
a name to a container port, for example `{"http": 8080}`. `env`, `secrets`,
and `volumes` inject configuration.

`authorized=True` requires a bearer token on the pod's URL. `tcp=True`
exposes raw TCP instead of HTTP. `block_network=True` cuts outbound access;
`allow_list=[...]` permits named hosts instead.

`health_check_path` and `health_check_port` give the proxy an HTTP probe to
call before routing to a container. Without one, the proxy only checks that
the port accepts connections.

`checkpoint_enabled=True` lets you checkpoint a running pod. It needs
`checkpoint_readiness_path` and `checkpoint_readiness_port`, an HTTP probe
checked before the snapshot is taken.

`docker_enabled=True` gives the pod its own Docker daemon. `pool` picks the
compute pool.

`web.configure(...)` returns the pod with changed settings, and `web.shell()`
opens a shell in a pod container.

## Containers

```bash
lazycloud container list
lazycloud container attach <container-id>      # stream output until it exits
lazycloud container checkpoint <container-id>
lazycloud container stop <container-id>
```
