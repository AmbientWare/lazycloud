A pod runs a container command, such as a web server or a model server. It fits
when you already have a command or image to run. For Python you want to call as
a function or serve over HTTP, an [endpoint](/concepts/endpoints) needs less
setup.

## Define a web server

Save this as `tools.py`:

```python
from lazycloud import App, Image

app = App("tools")

web = app.pod(
    name="web",
    image=Image(python_version="3.12"),
    command=["python", "-m", "http.server", "8080"],
    ports={"http": 8080},
    cpu=0.5,
    memory="256Mi",
    authorized=True,
)
```

Pods are public unless you set `authorized=True`, which this example does.
`keep_warm` is how long a container stays up with no connections, 600 seconds
by default. `keep_warm=-1` keeps it up regardless. Other defaults are in
[Resources and options](/concepts/resources#defaults).

## Deploy it

`lazycloud deploy` runs the pod under a deployment and prints its URL. This
example serves the container's current directory and requires a LazyCloud
bearer token. For a model server your application can call, see the
[vLLM example](/examples/openai-compatible-llm).

```bash
uv run lazycloud deploy tools:web
```

The Python definition holds the pod's image, command, resources, and mounts.
Changing any of them means editing the definition and deploying again.

A deployed pod runs one container while it has connections and stops it after
`keep_warm` seconds without any. The next request then waits while a new
container starts. A model server that must answer without that delay needs
`keep_warm=-1`, which holds one container up until you stop the deployment.
Pods do not autoscale on load. More than one container means setting the count
by hand:

```bash
uv run lazycloud deployment list --app tools
uv run lazycloud deployment scale web --containers 2
uv run lazycloud deployment stop web
```

`scale` pins the deployment to that many containers until you scale again.
`--containers 0` stops them all unless the pod is always-on. From Python,
`web.scale(containers)`, `web.pause()`, `web.resume()`, and `web.delete()` do
the same.

## Or create an instance on demand

A pod can also run once without a deployment. With an
[access token](/platform/auth#ci-and-scripts) in `LAZYCLOUD_TOKEN`, this starts
an instance, fetches the directory listing, and stops it:

```python
import os
import urllib.request

from tools import web

instance = web.create()
try:
    request = urllib.request.Request(
        instance.url,
        headers={"Authorization": f"Bearer {os.environ['LAZYCLOUD_TOKEN']}"},
    )
    with urllib.request.urlopen(request, timeout=60) as response:
        print(response.read().decode())
finally:
    instance.terminate()
```

`create()` uses the configured command. `web.run("python", "--version")`
starts an instance with a different command. Both return a `PodInstance` with
`container_id`, `url`, `timeout_seconds`, `expires_at`, and `terminate()`. The
instance lives for `keep_warm` seconds unless you pass `timeout_seconds`.

## Options

`command` sets what runs, and `ports` sets what it listens on. `ports` maps a
name to a container port, for example `{"http": 8080}`. `env`, `secrets`,
and `volumes` inject configuration.

`authorized=True` requires a bearer token on the pod's HTTP URL.
`block_network=True` cuts outbound access. `allow_list=[...]` limits outbound
access to IP networks in CIDR notation. It does not accept hostnames.

`health_check_path` and `health_check_port` give the proxy an HTTP probe to
call before routing to a container. Without one, the proxy only checks that
the port accepts connections.

`checkpoint_enabled=True` lets you checkpoint a running pod. It needs
`checkpoint_readiness_path` and `checkpoint_readiness_port`, which define an
HTTP probe LazyCloud checks before taking the snapshot.

`docker_enabled=True` gives the pod its own Docker daemon. `machine` names a
joined machine the pod must run on.

`web.shell()` opens a shell in a pod container.

## TCP connections

A TCP pod sets `tcp=True`, declares the server's port, and deploys with
`pod.deploy()`. TCP pods are public, with `authorized=False`, so your server
must authenticate its own clients.

The deployment returns a `tls://hostname:port` address. Connect with TLS and send
that hostname as SNI.

```python
import socket
import ssl
from urllib.parse import urlsplit

from lazycloud import App, Image

app = App("tcp_example")
tcp_server = app.pod(
    name="tcp-web",
    image=Image(python_version="3.12"),
    command=["python", "-m", "http.server", "8080"],
    ports={"http": 8080},
    tcp=True,
    authorized=False,
)

deployment = tcp_server.deploy()
address = urlsplit(deployment.invoke_url)
with socket.create_connection((address.hostname, address.port)) as connection:
    with ssl.create_default_context().wrap_socket(
        connection, server_hostname=address.hostname
    ) as stream:
        stream.sendall(b"GET / HTTP/1.0\r\n\r\n")
        print(stream.recv(1024))
```

This public example serves the container's directory over TLS until
`uv run lazycloud deployment stop tcp-web` stops it.

## Inspect running containers

`uv run lazycloud container list`, `attach`, `checkpoint`, and `stop` act on
individual pod containers. See
[container commands](/cli/deployments-and-containers#lazycloud-container). An
active deployment replaces a stopped container, so a service stays down only
once its deployment stops.
