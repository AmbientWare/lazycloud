A function is Python that returns a result: process a file, run inference,
build a report. Decorate it with `@app.function` and call it with `.remote()` or
`lazycloud run`. For HTTP callers use an [endpoint](/concepts/endpoints); for
recurring runs add a [schedule](/concepts/schedules).

## Define and call a function

Save this as `reports.py`:

```python
from lazycloud import App

app = App("reports")


@app.function(cpu=1, memory="256Mi", timeout_seconds=60, retries=0)
def summarize_sales(amounts_cents: list[int]) -> dict[str, int]:
    print(f"Summarizing {len(amounts_cents)} sales", flush=True)
    return {"sales": len(amounts_cents), "total_cents": sum(amounts_cents)}
```

From the CLI, JSON arguments become Python values:

```bash
uv run lazycloud run reports:summarize_sales '[1200, 3500, 800]'
```

From Python:

```python
from reports import summarize_sales

print(summarize_sales.remote([1200, 3500, 800]))
```

Both stream the function's logs, then return three sales totaling 5500 cents.
`await summarize_sales.async_remote(...)` is the async form.
`summarize_sales.local(...)` runs it in your own process;
[Run, preview, deploy](/concepts/workflow) covers when to use each, and how
`.remote()` picks a preview or deployment.

## Process a batch

`.map()` submits one call per input and yields results in input order. Each
tuple holds one call's arguments:

```python
from reports import summarize_sales

for result in summarize_sales.map([([1200, 3500],), ([800, 900],)]):
    print(result)
```

A failed call yields `None`. When every item must succeed before you use the
batch, use `spawn_map()` and check each outcome:

```python
calls = summarize_sales.spawn_map([([1200, 3500],), ([800, 900],)])
outcomes = [call.result(wait=True) for call in calls]
failed = [outcome.error for outcome in outcomes if not outcome.ok]
if failed:
    raise RuntimeError(failed)
print([outcome.value for outcome in outcomes])
```

Without an autoscaler the calls run one at a time in one container. To run them
in parallel, let the function start more containers:

```python
from lazycloud import QueueDepthAutoscaler


@app.function(
    cpu=1,
    memory="512Mi",
    max_pending_tasks=1000,
    autoscaler=QueueDepthAutoscaler(max_containers=20, tasks_per_container=1),
)
def count_words(text: str) -> int:
    return len(text.split())
```

A `.map()` over 1,000 texts now runs on up to 20 containers at once.
`max_pending_tasks` is raised because `.map()` submits every input up front and
the default cap is 100. [Scaling and concurrency](/concepts/scaling) covers
running several calls per container and keeping containers warm.
[Parallel Parquet processing](/examples/parallel-parquet-s3) is a complete batch
workflow.

## Submit work in the background

```python
call = summarize_sales.spawn([1200, 3500, 800])
print(call.task_id)
value = call.get()
```

`.spawn()` returns a `FunctionCall` without waiting. Call `.get()` when you need
the value, or collect it later from another process with
`uv run lazycloud task result <task-id>`. `async_spawn()` is the awaitable form.
[Tasks and logs](/concepts/tasks-and-logs) covers reconnecting to a call by ID.

A function can take a pending `FunctionCall` as an argument; the callee receives
its result.

## Arguments and results

Calls from the Python SDK preserve serializable Python values, including NumPy
arrays, dataclasses, custom class instances, tuples, and bytes:

```python
import numpy as np
from lazycloud import App, Image

app = App("matrices")
image = Image(python_version="3.12").add_python_packages(["numpy>=2,<3"])


@app.function(image=image)
def matrix() -> np.ndarray:
    return np.arange(6, dtype=np.int64).reshape(2, 3)
```

The caller needs the same packages, and the same code for custom classes, at
matching versions. Only load results from code you trust, because unpickling can
execute code.

HTTP calls, the dashboard playground, `lazycloud run --json`, and
[exported client packages](/concepts/apps#call-deployed-workloads-from-other-projects)
need JSON-compatible values. Arguments and results are limited to 16 MiB each;
store larger output in a [volume](/concepts/volumes) or as an
[artifact](/concepts/artifacts) and return its path.

## Retries and timeouts

`timeout_seconds` caps one attempt. `retries` is the number of extra attempts
after a failure, 3 by default, so a function that writes somewhere can run four
times for one call. Make writes safe to repeat, or set `retries=0`. For
backoff, pass a `RetryPolicy`:

```python
import urllib.request

from lazycloud import RetryBackoff, RetryPolicy


@app.function(
    retry_policy=RetryPolicy(
        max_attempts=4,
        delay_seconds=2,
        backoff=RetryBackoff.Exponential,
        max_delay_seconds=30,
    ),
)
def fetch_text(url: str) -> str:
    with urllib.request.urlopen(url, timeout=30) as response:
        return response.read().decode("utf-8")
```

Retries also cover preempted capacity; see
[Preemptible capacity](/concepts/resources#preemptible-capacity).

## Lifecycle hooks

`on_start` runs before a container accepts calls. Use it to load a model or open
a client once instead of on every call:

```python
MODEL = {}


def load_model() -> None:
    MODEL["classifier"] = load_classifier()  # your loading code


@app.function(gpu="l4", on_start=load_model)
def classify(text: str) -> str:
    return MODEL["classifier"](text)
```

With `concurrency` above one, `on_start` runs in each call slot's process, or
once per container with `in_process=True`; see
[Scaling](/concepts/scaling#functions).

Per-call hooks are `on_running`, `on_success`, `on_error`, `on_retry`,
`on_failure`, and `on_finish`. Each takes a callable, a decorated function, a
dotted import string, or a list of them. Inside a hook or the function,
`lazycloud.current_task_id()` identifies the current call; prefer it to the
`TASK_ID` environment variable when calls share a process.

Put packages in an [image](/concepts/images), credentials in
[secrets](/concepts/secrets), files that outlive the container in
[volumes](/concepts/volumes), and plain settings in `env`. Every decorator
