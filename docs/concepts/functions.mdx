---
title: "Functions"
description: "Python that runs in a remote container and returns its result, one call at a time or fanned out over a batch."
---

A function fits batch jobs, background work, and GPU tasks that your code or a
person calls. HTTP callers suit an [endpoint](/concepts/endpoints), and
recurring runs a [schedule](/concepts/schedules).

## Define a function

Save this as `reports.py`:

```python
from lazycloud import App

app = App("reports")


@app.function(cpu=1, memory="256Mi", timeout_seconds=60, retries=0)
def summarize_sales(amounts_cents: list[int]) -> dict[str, int]:
    print(f"Summarizing {len(amounts_cents)} sales", flush=True)
    return {"sales": len(amounts_cents), "total_cents": sum(amounts_cents)}
```

## Call it

From the CLI, JSON arguments become Python values:

```bash
uv run lazycloud run reports:summarize_sales '[1200, 3500, 800]'
```

From Python:

```python
from reports import summarize_sales

print(summarize_sales.remote([1200, 3500, 800]))
```

Both run the function in a cloud container, stream its logs to your terminal,
and return three sales totaling 5500 cents.
`await summarize_sales.async_remote(...)` is the async form.
`summarize_sales.local(...)` runs it in your own process.
[Develop, test, deploy](/concepts/workflow) covers when to use each and how
`.remote()` chooses between a preview and a deployment.

### Process a batch

`.map()` submits one call per input and yields results in input order. Each
tuple holds one call's arguments:

```python
from reports import summarize_sales

for result in summarize_sales.map([([1200, 3500],), ([800, 900],)]):
    print(result)
```

A failed call yields `None`. When every item must succeed before you use the
batch, `spawn_map()` returns each outcome to check:

```python
calls = summarize_sales.spawn_map([([1200, 3500],), ([800, 900],)])
outcomes = [call.result(wait=True) for call in calls]
failed = [outcome.error for outcome in outcomes if not outcome.ok]
if failed:
    raise RuntimeError(failed)
print([outcome.value for outcome in outcomes])
```

Without an autoscaler the calls run one at a time in one container. An
autoscaler lets the function start more containers and run them in parallel:

```python
from lazycloud import QueueDepthAutoscaler


@app.function(
    cpu=1,
    memory="512Mi",
    max_pending_tasks=1000,
    autoscaler=QueueDepthAutoscaler(max_containers=20, tasks_per_container=1),
)
def count_words(text: str) -> int:
    return len(text.split())
```

A `.map()` over 1,000 texts now runs on up to 20 containers at once. The
example raises `max_pending_tasks` because `.map()` submits every input up
front and the default cap is 100. [Scaling and concurrency](/concepts/scaling)
covers running several calls per container.
[Parallel Parquet processing](/examples/parallel-parquet-s3) is a complete batch
workflow.

### Submit work in the background

```python
call = summarize_sales.spawn([1200, 3500, 800])
print(call.task_id)
value = call.get()
```

`.spawn()` returns a `FunctionCall` without waiting. `.get()` waits for the
value, and `uv run lazycloud task result <task-id>` collects it later from
another process. `async_spawn()` is the awaitable form.
[Tasks and logs](/concepts/tasks-and-logs) covers reconnecting to a call by ID.

You can pass a pending `FunctionCall` as an argument to another function. The
callee receives the call's result.

### Arguments and results

Calls from the Python SDK carry any serializable Python value, including NumPy
arrays, dataclasses, custom class instances, tuples, and bytes:

```python
import numpy as np
from lazycloud import App, Image

app = App("matrices")
image = Image(python_version="3.12").add_python_packages(["numpy>=2,<3"])


@app.function(image=image)
def matrix() -> np.ndarray:
    return np.arange(6, dtype=np.int64).reshape(2, 3)
```

The caller needs the same packages at matching versions, plus the same code
for any custom class. Unpickling can execute code, so only load results from
code you trust.

HTTP calls, the dashboard playground, `lazycloud run --json`, and
[exported client packages](/concepts/apps#call-deployed-workloads-from-other-projects)
need JSON-compatible values. Each argument payload and result can be at most
16 MiB. Larger output fits in a [volume](/concepts/volumes) or an
[artifact](/concepts/artifacts), with the call returning its path.

## Function options

### Retries and timeouts

`timeout_seconds` caps one attempt. `retries` sets how many extra attempts
follow a failure. The default is 3, so one call can run the function four
times, and an attempt can fail after doing part of its work. A function that
writes somewhere needs writes that are safe to repeat, such as an output path
or record keyed on the input, or `retries=0`. A `RetryPolicy` adds backoff:

```python
import urllib.request

from lazycloud import RetryBackoff, RetryPolicy


@app.function(
    retry_policy=RetryPolicy(
        max_attempts=4,
        delay_seconds=2,
        backoff=RetryBackoff.Exponential,
        max_delay_seconds=30,
    ),
)
def fetch_text(url: str) -> str:
    with urllib.request.urlopen(url, timeout=30) as response:
        return response.read().decode("utf-8")
```

Retries also cover preempted capacity, so a function on the default
[preemptible capacity](/concepts/resources#preemptible-capacity) can run again
even when its code never fails. Each retry reuses the same task.

### Lifecycle hooks

`on_start` runs before a container accepts calls. It loads a model or opens a
client once instead of on every call:

```python
from lazycloud import GpuType

MODEL = {}


def load_model() -> None:
    MODEL["classifier"] = load_classifier()  # your loading code


@app.function(gpu=GpuType.L4, on_start=load_model)
def classify(text: str) -> str:
    return MODEL["classifier"](text)
```

With `concurrency` above one, `on_start` runs in each call slot's process.
With `in_process=True` it runs once per container. See
[Scaling](/concepts/scaling#functions).

Per-call hooks are `on_running`, `on_success`, `on_error`, `on_retry`,
`on_failure`, and `on_finish`. Each takes a callable, a decorated function, a
dotted import string, or a list of them. Inside the function or a hook,
`lazycloud.current_task_id()` returns the current call's task ID.

## Stop and clean up

A call's container stops after the function's idle window. See
[Warm containers](/concepts/scaling#warm-containers).
`uv run lazycloud task cancel <task-id>` cancels a pending call, and
`task stop` stops a running one.

A deployed function stays callable until you stop it:

```bash
uv run lazycloud deployment stop summarize_sales
uv run lazycloud deployment delete summarize_sales
```

`stop` keeps the definition for `deployment start`. Deleting the function from
the code and deploying with [`--prune`](/concepts/apps#remove-workloads) also
removes it.
