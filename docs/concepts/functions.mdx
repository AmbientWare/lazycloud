Use a function for work that returns a result, such as processing a file,
running inference, or generating a report. Add `@app.function` and call it
with `.remote()` or `uv run lazycloud run`.

## Run a function

Save this as `reports.py`:

```python
from lazycloud import App

app = App("reports")


@app.function(cpu=1, memory="256Mi", timeout_seconds=60, retries=0)
def summarize_sales(amounts_cents: list[int]) -> dict[str, int]:
    print(f"Summarizing {len(amounts_cents)} sales", flush=True)
    return {"sales": len(amounts_cents), "total_cents": sum(amounts_cents)}


if __name__ == "__main__":
    print(summarize_sales.remote([1200, 3500, 800]))
```

```bash
uv run lazycloud run reports:summarize_sales '[1200, 3500, 800]'
```

The command shows progress and logs, then returns three sales totaling 5500
cents. It prepares the image and uploads your source automatically.
You can also run `uv run python reports.py`.

## Choose how to call it

```python
from reports import summarize_sales

result = summarize_sales.remote([1200, 3500, 800])
print(result)
```

`.remote()` submits a task and returns its result. For async code, use
`await summarize_sales.async_remote(...)`.

Calling `summarize_sales(...)` or `summarize_sales.local(...)` runs in the
current Python process. Local calls do not use the image, mounted volumes,
secrets, retries, or lifecycle hooks from the decorator.

When one remote function calls another with `.remote()`, the callee must
already be deployed. Deploy the app containing both before running the parent:

```bash
uv run lazycloud deploy reports:app
```

## Return Python objects

Python SDK calls preserve serializable Python values, including NumPy arrays,
custom class instances, dataclasses, tuples, and bytes. For example:

```python
import numpy as np
from lazycloud import App, Image

app = App("matrices")
image = Image(python_version="3.12").add_python_packages(["numpy>=2,<3"])


@app.function(image=image)
def matrix() -> np.ndarray:
    return np.arange(6, dtype=np.int64).reshape(2, 3)


if __name__ == "__main__":
    result = matrix.remote()
    print(result.shape, result.dtype)
```

Install NumPy in the calling environment too. Use `np.ndarray` or
`numpy.typing.NDArray` as the annotation; `np.array` is a constructor.
Custom classes defined in importable modules require that code on the caller.
Use matching Python and dependency versions in the caller and container.

Python calls bind arguments using the function's signature without converting
them based on annotations. Explicit `inputs` and `outputs` schemas still validate
values. `.async_remote()`, `.spawn().get()`, and `.map()` use the same result
serialization. A function can also receive a previous `FunctionCall` as an argument.
Dependencies can appear inside containers or custom objects. Their results replace
the call references while preserving collection types, cycles, and shared references.

HTTP calls, the JSON playground, and exported JSON client packages require
JSON-compatible contracts. Call Python-only functions through their source SDK
objects by importing the decorated function and calling `.remote()`. Only load
Python objects from code you trust. Unpickling can execute code.

Serialized arguments and results are limited to 16 MiB each. Store larger outputs
as artifacts and return a reference. Live connections, locks, and generators
are not portable return values.

## Preview while you edit

Keep a preview running in one terminal:

```bash
uv run lazycloud serve reports:summarize_sales
```

Call it from a second terminal:

```bash
uv run lazycloud run reports:summarize_sales '[1200, 3500, 800]'
```

Calls from the same local configuration use the preview while it is active.
Source edits reload after active calls finish. The preview keeps its container
warm until you press Ctrl+C in the first terminal.

## Process several inputs

`.map()` submits one task per input and yields results in input order:

```python
from reports import summarize_sales

for result in summarize_sales.map([([1200, 3500],), ([800, 900],)]):
    print(result)
```

Each tuple holds the arguments for one call. Here, each call takes one list.
A failed task yields `None`. If every item must succeed before you use the
batch, use `spawn_map()` and check each outcome:

```python
calls = summarize_sales.spawn_map([([1200, 3500],), ([800, 900],)])
outcomes = [call.result(wait=True) for call in calls]
for outcome in outcomes:
    if not outcome.ok:
        raise RuntimeError(outcome.error or "Sales summary failed")
print([outcome.value for outcome in outcomes])
```

See [Parallel Parquet processing](/examples/parallel-parquet-s3) for a
complete batch workflow that writes output only after every task succeeds.

## Submit work in the background

```python
from reports import summarize_sales

call = summarize_sales.spawn([1200, 3500, 800])
print(call.task_id)
```

`.spawn()` returns a `FunctionCall` without waiting for the result.
Use `call.get()` when you need the value, or retrieve it later with
`uv run lazycloud task result <task-id>`. `async_spawn()` is the awaitable form.

## Progress and logs

Local `.remote()` calls and `uv run lazycloud run` show image-build progress,
source uploads, task status, and remote stdout and stderr. Use a separate
[log command](/concepts/tasks-and-logs) when revisiting a run or following
background work.

Progress and remote logs go to stderr. The CLI prints the result to stdout;
Python returns it to your caller. To suppress progress in a Python block:

```python
from lazycloud import output
from reports import summarize_sales

with output(enabled=False):
    result = summarize_sales.remote([1200, 3500, 800])
print(result)
```

Calls made inside LazyCloud containers are quiet by default. `with output():`
enables their output. Silencing output leaves exceptions and stored logs intact.

## Choose resources and retry behavior

Set `cpu`, `memory`, and, for GPU work, `gpu` and `gpu_count` on the
decorator. Defaults are `cpu=0.125`, `memory="128Mi"`,
`timeout_seconds=3600`, and `retries=3`.

`timeout_seconds` caps each invocation. `retries` sets the number of
additional attempts after failure. Make writes safe to repeat before enabling
retries. Use a retry policy for exponential backoff:

```python
import urllib.request

from lazycloud import RetryBackoff, RetryPolicy


@app.function(
    retry_policy=RetryPolicy(
        max_attempts=4,
        delay_seconds=2,
        backoff=RetryBackoff.Exponential,
        max_delay_seconds=30,
    ),
)
def fetch_text(url: str) -> str:
    with urllib.request.urlopen(url, timeout=30) as response:
        return response.read().decode("utf-8")
```

## Warm containers and concurrency

`keep_warm` keeps an idle container available between calls, for 10 seconds
by default. Set it to `0` to release the container when idle. Warm containers
continue to incur compute charges.

`concurrency` sets how many calls a container handles at once. By default,
each slot uses its own process. `in_process=True` shares one interpreter,
which can avoid loading a GPU model once per process. CPU-bound Python code
in those slots contends for the GIL.

With multiple process slots, cancelling a call replaces only its slot. Other
slots continue in the same container. Cancelling a single-slot function or an
`in_process=True` function stops the container. Other calls in a shared
interpreter restart and may repeat partial side effects.

To add containers as calls queue up:

```python
from lazycloud import QueueDepthAutoscaler


@app.function(
    autoscaler=QueueDepthAutoscaler(
        min_containers=0,
        max_containers=8,
        tasks_per_container=2,
    ),
)
def count_words(text: str) -> int:
    return len(text.split())
```

`min_containers` keeps that many containers running even without work.
`max_pending_tasks` limits calls in flight; excess calls receive a capacity error.

## Understand a pending call

After five seconds pending, the CLI and dashboard show the available reason,
such as compute startup, busy containers, or a retry. For progress in your own UI:

```python
import lazycloud
from reports import summarize_sales


def report_progress(task_id: str, pending: lazycloud.TaskPendingProgress | None) -> None:
    if pending is not None:
        print(task_id, pending.reason, pending.message)


with lazycloud.progress(report_progress):
    result = summarize_sales.remote([1200, 3500, 800])
```

The callback receives `None` when the pending explanation clears.
`call.task.pending_progress` reads it for a submitted call.

## Add dependencies and data

Use an [Image](/concepts/images) for packages, [secrets](/concepts/secrets)
for credentials, and [volumes](/concepts/volumes) for files that must survive
the container. Plain configuration belongs in `env`.

## Initialize a container or handle failures

`on_start` runs when a container boots, before it accepts calls. Use it to
load a model or initialize a client. Per-task hooks are `on_running`,
`on_success`, `on_error`, `on_retry`, `on_failure`, and `on_finish`.
Each accepts a callable, a decorated function, a dotted import string, or a list.

Inside a handler, `lazycloud.current_task_id()` identifies the current call.
Use it instead of the `TASK_ID` environment variable when calls share a process.

## Debug the remote environment

```bash
uv run lazycloud shell reports:summarize_sales
```

This opens a shell in the function's image so you can inspect packages and files.
