Use `@app.function` for Python that should run remotely and does not need an
HTTP route. The decorated object keeps the callable's argument and return
types.

```python
from lazycloud import App, Image

app = App("reports")
image = Image(python_version="3.12").add_python_packages(["pandas"])


@app.function(image=image, cpu=2.0, memory="1Gi", timeout_seconds=600, retries=2)
def build_report(month: str) -> dict[str, str]:
    return {"month": month, "status": "built"}
```

Deploy it with `lazycloud deploy reports.py:build_report` or
`build_report.deploy()`.

## Call it

```python
build_report.local("2026-06")     # runs in your own process
build_report.remote("2026-06")    # runs on LazyCloud and returns the result
build_report("2026-06")           # same as .remote(...)

handle = build_report.spawn("2026-06")   # returns a FunctionCall without waiting
handle.task_id
handle.get()                             # waits for the value

for result in build_report.map(["2026-05", "2026-06"]):   # one task per input
    ...
handles = build_report.spawn_map(["2026-05", "2026-06"])
```

`async_remote` and `async_spawn` are the awaitable forms. A `FunctionCall`
carries the task id; see [Tasks and logs](/concepts/tasks-and-logs) for
results, waiting, and logs.

From the CLI, `lazycloud run reports.py:build_report 2026-06` submits one call
and prints the result. An argument that parses as JSON is passed as that
value; anything else is a string.

## Sizing, timeouts, and retries

Functions default to `cpu=0.125`, `memory="128Mi"`, `timeout_seconds=3600`,
and `retries=3`.

`timeout_seconds` caps one invocation. A run that exceeds it ends with status
`timeout`. `retries` is the number of attempts after a failure, with
`retry_delay_seconds` between them. For backoff, pass a `RetryPolicy`:

```python
from lazycloud import RetryBackoff, RetryPolicy


@app.function(
    retry_policy=RetryPolicy(
        max_attempts=4,
        delay_seconds=2.0,
        backoff=RetryBackoff.Exponential,
        max_delay_seconds=30.0,
    ),
)
def flaky_ingest(url: str) -> int: ...
```

## Warm containers and concurrency

A container stays up for `keep_warm` seconds after a call finishes, 10 by
default, so a call arriving inside that window reaches an interpreter that has
already imported your code and run `on_start`. Set `keep_warm=0` to retire a
container as soon as it goes idle.

`concurrency` is how many calls one container serves at once. Each slot runs
in its own process by default, so calls cannot disturb each other and CPU-bound
work runs in parallel.

`in_process=True` puts the slots in one interpreter instead. Use it when the
slots must share something a process cannot duplicate. A model loaded onto a
GPU by `on_start` is loaded once and served by every slot; with separate
processes, four slots would try to load four copies. The trade is Python's:
CPU-bound handlers contend for the GIL, so it suits work that waits on a
device, a network call, or a library that releases the lock.

```python
@app.function(gpu="a100-80", gpu_count=1, concurrency=8, in_process=True, on_start=load_model)
def embed(text: str) -> list[float]:
    return MODEL.encode(text).tolist()
```

Inside a handler, read the current task id with `lazycloud.current_task_id()`.
Several calls can share one environment, so the `TASK_ID` environment variable
is not per call.

`max_pending_tasks` caps how many calls a function has in flight; a call past
the cap is refused with a capacity error rather than queued.

Queue-depth autoscaling adds containers when calls back up:

```python
from lazycloud import QueueDepthAutoscaler


@app.function(autoscaler=QueueDepthAutoscaler(min_containers=0, max_containers=8, tasks_per_container=2))
def transcribe(path: str) -> str: ...
```

`min_containers` keeps that many containers up with nothing queued, which also
makes the keep-warm window infinite for them.

## Secrets and environment

`env` sets plain environment variables. `secrets` injects
[workspace secrets](/concepts/secrets) by name, each as an environment
variable with the same name:

```python
@app.function(env={"REGION": "us-east-1"}, secrets=["OPENAI_API_KEY"])
def summarize(text: str) -> str: ...
```

## Volumes

Mount [volumes and cloud buckets](/concepts/volumes) at a path:

```python
from lazycloud import Volume


@app.function(volumes=[Volume("models", "/models")])
def load_model(name: str) -> str: ...
```

## Lifecycle hooks

`on_start` runs once when a container boots, before its first call. Load
models and warm caches there. The other hooks run at each stage of a task:
`on_running`, `on_success`, `on_error`, `on_retry`, `on_failure`,
`on_cancelled`, `on_timeout`, and `on_finish`. A hook is a callable, a
decorated function, or a dotted import string, and each option also takes a
list.

```python
def notify_failure() -> None:
    print("report build failed", flush=True)


@app.function(retries=1, on_failure=notify_failure)
def build_daily() -> None: ...
```

## Debugging

`build_report.shell()` or `lazycloud shell reports.py:build_report` opens an
interactive shell in the function's image.
