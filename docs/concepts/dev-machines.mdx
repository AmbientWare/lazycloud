---
title: "Devboxes"
description: "A container you log into over SSH, with a disk that keeps its files, for coding agents and remote editors."
---

`app.devbox(...)` declares a container you reach over SSH whose root filesystem
is a [disk](/concepts/disks). It runs while something is connected and stops
after 30 idle minutes. Packages, dotfiles and code stay on the disk from one
start to the next, on whichever machine it lands.

## Define one

Save this as `dev.py`:

```python
from lazycloud import App, Image

app = App("dev")

box = app.devbox(
    "box",
    image=Image(python_version="3.12"),
    disk="100Gi",
    cpu=4,
    memory="16Gi",
)
```

```bash
uv run lazycloud deploy dev:box
uv run lazycloud ssh box
```

`lazycloud ssh` opens a shell as `root` in `/root`. The app's source is not
mounted, so `git clone` your code onto the disk. The image needs no `sshd`.

`disk=` sizes the root disk, which is named after the devbox.
[Disk pricing](/concepts/disks#pricing) covers what it costs.

## Coding agents

Devboxes install Codex, Claude Code, OpenCode, Pi, Node.js 22, Git, and process
utilities required by the selected agents, such as `ps` for Codex, when the image
builds. The SDK pins the agent and Node.js versions.
Import `AgentHarness` from `lazycloud` and pass
`agent_harnesses=[AgentHarness.Codex]` to install only Codex, or
`agent_harnesses=[]` to skip agent installation.

Installation requires a Debian or Ubuntu image with root build access. Pass
`agent_harnesses=[]` when using `Image.from_id()` or an image that supplies its
own tools.

After deployment, authenticate from an interactive terminal on your laptop:

```bash
lazycloud devbox login box codex
lazycloud devbox login box claude-code
lazycloud devbox login box opencode
lazycloud devbox login box pi
```

The command checks that the agent and its required system commands are installed
on the devbox. If any are missing, it stops and prints installation instructions
to run inside the devbox. It does not install or upgrade packages during login.

The command starts the agent's login on the devbox and opens your laptop's
browser. SSH carries the localhost callback back to the devbox. You don't need
a public `ports` entry or device-code authentication. The agent saves its
credentials on the devbox disk, outside the built image.

For Claude Code, the command verifies the saved login and completes its first-run
configuration before closing the connection. An existing login is reused. To
switch accounts, run `claude auth logout` inside the devbox before logging in
again. Project trust and permission prompts still appear when you start Claude.

OpenCode prompts for a provider and login method. Select browser login. In Pi,
run `/login`, select the provider's browser login, and exit Pi when finished.
Available methods depend on the provider. API keys can also be supplied through
[secrets](/concepts/secrets).

Browser login requires OpenSSH and a browser on your macOS, Linux, or WSL
computer. Run the command locally; a dashboard terminal cannot forward a
callback from your laptop. Finish one login before starting another that uses the
same port. If a local service already occupies the port, the command fails
before opening the browser.

Anyone with access to the devbox can read its saved credentials. Use separate
devboxes for separate accounts.

## What persists

Everything under `/` is on the disk, except:

- `/dev/shm` and `/volumes`: memory, empty on each start
- [Volumes](/concepts/volumes) you attach: kept in the volume
- `/artifacts`: the app's artifacts, read-only
- `/etc/hosts`, `/etc/resolv.conf`, `/run/lazycloud`: rewritten on each start

## What a devbox defaults to

`deploy` prints the resolved settings:

| Setting | Default | Override |
| --- | --- | --- |
| Idle time before it stops | 30 minutes | `keep_warm=` seconds, or `-1` to keep it running |
| Capacity | Not reclaimable, so a session is never cut off by a reclaim | `preemptible=True` |
| Command | Keeps the container running | `command=[...]` |
| Containers | One, since one container writes a disk at a time | none |

`disks=` adds more disks at other paths. Other options work as they do on a
[pod](/concepts/pods).

## Remote editors

```bash
uv run lazycloud ssh-config
```

This adds a host named `lazycloud-<workspace>-<app>-<name>` for each devbox to
`~/.ssh/config`, so VS Code and Cursor Remote-SSH list it and plain `ssh` works.
Connections go through the LazyCloud API with a short-lived certificate the
config refreshes, so there are no keys to copy.

## When it runs

Connecting starts a stopped devbox, and the terminal shows each step until it
is up. An open SSH session keeps it running; the idle time counts from when the
last one closes. On the devbox's dashboard page, Start boots it and Stop ends it.

## Stop and clean up

```bash
uv run lazycloud deployment stop box
uv run lazycloud deployment delete box
uv run lazycloud disk delete box
uv run lazycloud ssh-config --prune
```

Stopping or deleting the devbox keeps its disk; deleting the disk removes its
files.

## The same thing as a pod

A devbox is a [pod](/concepts/pods) with a role. `app.pod(ssh=True,
disks=[Disk("box-root", size="100Gi")], command=["sleep", "infinity"])` builds
the same machine with pod defaults, for when you need ports beside SSH or
several named disks.
