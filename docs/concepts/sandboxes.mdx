---
title: "Sandboxes"
description: "On-demand containers with process control, a filesystem API, exposed ports, snapshots, and optional Docker."
---

Sandboxes are on-demand containers for interactive and programmatic work:
running commands, editing files, exposing ports, and controlling processes.
They are ideal for code execution agents, dev environments, and untrusted
workloads.

```python
from lazycloud import App, Image

app = App("agents")

sandbox = app.sandbox(
    image=Image(python_version="3.12"),
    cpu=1.0,
    memory=1024,
    keep_warm_seconds=600,
)
```

Sandboxes default to `cpu=1.0`, `memory=128` (MiB), `keep_warm_seconds=600`,
and `authorized=False`. They are created on demand — `app.deploy()` does not
deploy them.

## Instances

```python
instance = sandbox.create()
print(instance.sandbox_id())

# Reconnect to a running sandbox later
same = sandbox.connect(instance.sandbox_id())

instance.update_ttl(1800)   # extend the idle lifetime
instance.terminate()
```

`sandbox.list()` returns the workspace's sandboxes, `sandbox.stats()`
aggregate counts, and `sandbox.timeline(stub_id)` the lifecycle timeline of
one sandbox.

## Running commands and processes

`run` executes a command and blocks for the response; the `process` manager
gives asynchronous control:

```python
result = instance.run("python --version")
print(result.exit_code, result.stdout)

proc = instance.process.exec("python", "-m", "http.server", "8000")
proc.wait()                      # or poll proc.status()
print(proc.stdout.read())        # stream stdout / stderr / combined logs
proc.kill()

instance.process.run_code("print(2 + 2)")   # run a Python snippet
instance.list_processes()
```

Processes expose `pid`, `wait(timeout)`, `kill()`, `status()`, and `stdout`,
`stderr`, and `logs` streams with `read()` and `lines()`.

## Filesystem

`instance.fs` operates on the sandbox filesystem (default working directory
`/workspace`):

```python
instance.fs.upload_file("model.pt", "/workspace/model.pt")
instance.fs.download_file("/workspace/out.json", "out.json")
instance.fs.list_files("/workspace")
instance.fs.stat_file("/workspace/model.pt")
instance.fs.create_directory("/workspace/data")
instance.fs.delete_file("/workspace/tmp.txt")
instance.fs.find_in_files("/workspace/src", "TODO")
instance.fs.replace_in_files("/workspace/src", "old", "new")
```

## Ports and networking

```python
url = instance.expose_port(8000)   # URL pinned to this sandbox instance
instance.list_urls()

instance.network_permissions()
instance.update_network_permissions(block_network=True, allow_list=["api.example.com"])
```

Each URL identifies the exact sandbox container. It never redirects to another
instance created from the same sandbox definition, and becomes unavailable when
that container stops. `list_urls()` returns the persisted exposures that the
worker still reports as active. Ports must be between 1 and 65535.
If the owning app's visibility changes, `list_urls()` returns and persists the
corresponding current public or authenticated URL; authorization always checks
the current workspace and app state.

Declare `ports=[8000]` on the sandbox definition to expose ports after the new
instance becomes ready.
`block_network` and `allow_list` set the outbound policy.

## Docker inside sandboxes

With `docker_enabled=True`, the sandbox gets an isolated Docker daemon and
`instance.docker` provides access to it for building and running containers
within the sandbox.

## Snapshots

```python
snapshot_id = instance.snapshot_memory()
restored = sandbox.create_from_memory_snapshot(snapshot_id)

image_id = instance.create_image_from_filesystem()
```

Memory snapshots restore a running sandbox's state; filesystem images capture
the disk as a reusable image id for `Image.from_id(...)`.

## Async API

Every surface has an async twin under `.aio` — for example
`await instance.aio.run(...)`, `await instance.process.aio.exec(...)`, and
`await instance.fs.aio.upload_file(...)`.

## Definition options

Sandboxes accept `env`, `secrets`, `volumes`, `gpu`/`gpu_count`,
`sync_local_dir` (copy your working directory into the sandbox at creation),
`command` (initial command), and the standard `pool`/`provider`
options. Inspect sandboxes in the [dashboard](/platform/dashboard) with a
terminal, file browser, and process list.
