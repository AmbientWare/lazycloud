---
title: "Sandboxes"
description: "On-demand containers with process control, a filesystem API, exposed ports, snapshots, and optional Docker."
---

A sandbox is a container you create when you need it, run commands in, move
files in and out of, and terminate. It suits code-execution agents, dev
environments, and untrusted workloads.

```python
from lazycloud import App, Image

app = App("agents")

sandbox = app.sandbox(
    image=Image(python_version="3.12"),
    cpu=1.0,
    memory=1024,
    keep_warm_seconds=600,
)

instance = sandbox.create()
result = instance.run("python --version")
print(result.exit_code, result.stdout)
instance.terminate()
```

Sandboxes default to `cpu=1.0`, `memory=128` (MiB), `keep_warm_seconds=600`,
and `authorized=False`. They are created on demand; `app.deploy()` does not
deploy them.

## Instances

```python
instance = sandbox.create()
sandbox_id = instance.sandbox_id()

same = sandbox.connect(sandbox_id)   # reconnect later
instance.update_ttl(1800)            # extend the idle lifetime
instance.terminate()
```

`sandbox.list()` returns the workspace's sandboxes, `sandbox.stats()` counts
them, and `sandbox.timeline(stub_id)` gives one sandbox's lifecycle.

## Commands and processes

`run` blocks until the command exits. `process` gives you control over
long-running ones:

```python
result = instance.run("pytest -q", cwd="/workspace", timeout_seconds=300)

proc = instance.process.exec("python", "-m", "http.server", "8000")
proc.wait()                    # or proc.status()
print(proc.stdout.read())      # stdout, stderr, and combined logs streams
proc.kill()

instance.process.run_code("print(2 + 2)")   # a Python snippet
instance.list_processes()
```

A process has `pid`, `wait(timeout)`, `kill()`, `status()`, and `stdout`,
`stderr`, and `logs` streams with `read()` and `lines()`.

## Files

`instance.fs` works on the sandbox filesystem. The working directory is
`/workspace`.

```python
instance.fs.upload_file("model.pt", "/workspace/model.pt")
instance.fs.download_file("/workspace/out.json", "out.json")
instance.fs.list_files("/workspace")
instance.fs.stat_file("/workspace/model.pt")
instance.fs.create_directory("/workspace/data")
instance.fs.delete_file("/workspace/tmp.txt")
instance.fs.find_in_files("/workspace/src", "TODO")
instance.fs.replace_in_files("/workspace/src", "old", "new")
```

## Ports and network

```python
url = instance.expose_port(8000)
instance.list_urls()

instance.network_permissions()
instance.update_network_permissions(block_network=True)
instance.update_network_permissions(allow_list=["api.example.com"])
```

An exposed URL points at this exact container. It never redirects to another
instance of the same sandbox, and it stops working when the container stops.
Declare `ports=[8000]` on the sandbox to expose ports as soon as an instance
is ready. `block_network` and `allow_list` set the outbound policy and cannot
be combined.

## Docker inside a sandbox

With `docker_enabled=True` the sandbox has its own Docker daemon, and
`instance.docker` wraps it: `run`, `build`, `pull`, `push`, `ps`, `logs`,
`stop`, `rm`, `exec`, `login`, `compose_up`, `compose_down`, and volume
commands.

## Snapshots

```python
snapshot_id = instance.snapshot_memory()
restored = sandbox.create_from_memory_snapshot(snapshot_id)

image_id = instance.create_image_from_filesystem()
```

A memory snapshot restores a running sandbox's state. A filesystem image
captures the disk as an image id you can reuse with `Image.from_id(...)`.

## Async

Every surface has an async twin under `.aio`: `await instance.aio.run(...)`,
`await instance.process.aio.exec(...)`, `await instance.fs.aio.upload_file(...)`.

## Definition options

Sandboxes also accept `env`, `secrets`, `volumes`, `gpu` and `gpu_count`,
`sync_local_dir=True` to copy your working directory in at creation,
`command` for the initial process, `docker_enabled`, and `pool`. Running
sandboxes appear on their app's page in the
[dashboard](/platform/dashboard) with a terminal, file browser, and process
list.
