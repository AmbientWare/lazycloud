title: "Tasks and logs"
description: "Every invocation is a durable task with a status, a result, and logs."
---

Remote function calls, endpoint requests, and scheduled runs create tasks.
Use task history to revisit a result, investigate a failure, or follow work
you submitted in the background.

`uv run lazycloud run` already shows progress, remote logs, and the result for a
function. You only need the commands here to inspect it separately.
Local Python calls do not create remote tasks.

## Lifecycle

A task is `pending` until a container picks it up, then `running`. If an
attempt fails and retries remain it is `retry`. It ends as `complete`,
`failed`, `timeout`, `cancelled`, or `expired`. Retries stay on the same task.

## From the CLI

```bash
uv run lazycloud task list                 # recent tasks, --app to filter by app
uv run lazycloud task show <task-id>       # status, timing, deployment, container
uv run lazycloud task result <task-id>     # waits for completion and prints the result
uv run lazycloud task logs <task-id>       # recent log lines
uv run lazycloud task stop <task-id> ...   # stop running tasks
uv run lazycloud task cancel <task-id>     # cancel a pending task
```

`task result --no-wait` returns the current state without waiting;
`--timeout <seconds>` bounds the wait.

## Logs

`uv run lazycloud logs` reads logs by deployment, task, or container, and `--follow`
streams them:

```bash
uv run lazycloud logs --task-id <task-id> --follow
uv run lazycloud logs --deployment predict -n 500 --show-timestamp
uv run lazycloud logs --container-id <container-id>
```

`--deployment` takes a deployment name or id. Anything your code prints to
stdout or stderr is captured. Print with `flush=True`, or run Python
unbuffered, so lines show up promptly.

## From Python

`spawn` returns a `FunctionCall`:

```python
from reports import summarize_sales

handle = summarize_sales.spawn([1200, 3500, 800])
print(handle.task_id)

result = handle.result(wait=True, timeout_seconds=120)
print(result.ok, result.status, result.value, result.error)
```

This uses `reports.py` from the [functions guide](/concepts/functions).
`handle.get(timeout_seconds=120)` returns the value or raises on failure.
`handle.logs()` reads stored logs.

For a task you only know by id, reconnect with `Task.from_id`:

```python
from lazycloud import Task

task = Task.from_id("<task-id>")
outcome = task.wait(timeout_seconds=120)
print(outcome.status, outcome.value)
```

Use `task.cancel()` to cancel pending work, or `uv run lazycloud task stop <task-id>`
to stop a running task.

Failed tasks keep the error message and the full logs.

## Callbacks

Every workload accepts `callback_url`. LazyCloud calls the webhook with
execution events as the task changes state, so another system can react
without polling.
