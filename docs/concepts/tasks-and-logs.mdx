---
title: "Tasks and logs"
description: "Every invocation is a durable task with a status, a result, and logs."
---

Every function call, endpoint request, scheduled run, and `lazycloud run` is
recorded as a task. A task keeps its status, timing, result or error, retry
history, and logs.

## Lifecycle

A task is `pending` until a container picks it up, then `running`. If an
attempt fails and retries remain it is `retry`. It ends as `complete`,
`failed`, `timeout`, `cancelled`, or `expired`. Retries stay on the same task.

## From the CLI

```bash
lazycloud task list                 # recent tasks, --app to filter by app
lazycloud task show <task-id>       # status, timing, deployment, container
lazycloud task result <task-id>     # waits for completion and prints the result
lazycloud task logs <task-id>       # recent log lines
lazycloud task stop <task-id> ...   # stop running tasks
lazycloud task cancel <task-id>     # cancel a pending task
```

`task result --no-wait` returns the current state without waiting;
`--timeout <seconds>` bounds the wait.

## Logs

`lazycloud logs` reads logs by deployment, task, or container, and `--follow`
streams them:

```bash
lazycloud logs --task-id <task-id> --follow
lazycloud logs --deployment predict -n 500 --show-timestamp
lazycloud logs --container-id <container-id>
```

`--deployment` takes a deployment name or id. Anything your code prints to
stdout or stderr is captured. Print with `flush=True`, or run Python
unbuffered, so lines show up promptly.

## From Python

`spawn` returns a `FunctionCall`:

```python
handle = my_function.spawn(42)
handle.task_id
handle.get(timeout_seconds=120)              # waits and returns the value, or raises

result = handle.result(wait=True, timeout_seconds=120)
result.ok, result.status, result.value, result.error
handle.logs()
```

For a task you only know by id, use `Client`:

```python
from lazycloud import Client

task = Client().task_handle("<task-id>")
outcome = task.wait(timeout_seconds=120)     # a TaskResult
task.logs()
task.cancel()
```

Failed tasks keep the error message and the full logs.

## Callbacks

Every workload accepts `callback_url`. LazyCloud calls the webhook with
execution events as the task changes state, so another system can react
without polling.
