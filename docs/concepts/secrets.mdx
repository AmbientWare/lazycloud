---
title: "Secrets"
description: "Store credentials in the workspace and inject them into workloads as environment variables."
---

Secrets hold API keys, tokens, and connection strings. They are encrypted at
rest, scoped to a workspace, and reach workloads only as environment
variables. Values never appear in deployment specs, logs, or the dashboard.

## Create and manage

```bash
lazycloud secret create OPENAI_API_KEY "$OPENAI_API_KEY"
lazycloud secret list
lazycloud secret show OPENAI_API_KEY            # metadata only
lazycloud secret show OPENAI_API_KEY --reveal   # prints the value
lazycloud secret modify OPENAI_API_KEY "$NEW_KEY"
lazycloud secret delete OPENAI_API_KEY
```

Read the value from a variable or a file rather than typing it into the
command, so it does not land in your shell history.

From Python:

```python
from lazycloud import Secret

secret = Secret("OPENAI_API_KEY")
secret.create(value)      # .set(value) creates or replaces, .update(value) replaces
secret.get()
secret.delete()
```

Secrets are also listed under Storage in the dashboard.

## Use in a workload

Name the secrets on the decorator. Each becomes an environment variable of the
same name inside the container:

```python
import os

from lazycloud import App

app = App("assistant")


@app.function(secrets=["OPENAI_API_KEY"])
def complete(prompt: str) -> str:
    api_key = os.environ["OPENAI_API_KEY"]
    ...
```

Image builds can use secrets through `Image.with_secrets([...])`, and
[cloud bucket mounts](/concepts/volumes#cloud-buckets) name the secrets that
hold their credentials.
