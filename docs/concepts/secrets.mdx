description: "Name the credentials a workload needs in code, keep their values in the workspace, and receive them as environment variables."

## Declare a credential dependency

Save this as `service.py`:

```python
import os
import urllib.request

from lazycloud import App, Secret

app = App("service_client")
api_key = Secret("SERVICE_API_KEY")


@app.function(secrets=[api_key.name], retries=0)
def fetch_status(url: str) -> str:
    request = urllib.request.Request(
        url,
        headers={"Authorization": f"Bearer {os.environ[api_key.name]}"},
    )
    with urllib.request.urlopen(request, timeout=30) as response:
        return response.read().decode("utf-8")
```

`Secret("SERVICE_API_KEY")` names the resource. It does not create a value.
Only workloads that list the name receive it. Names belong in source control,
and values in your local environment, CI secret store, or a masked prompt.

## Provision the value from Python

Save this as `configure_secrets.py` beside `service.py`:

```python
from getpass import getpass

from service import api_key


if __name__ == "__main__":
    api_key.set(getpass("Service API key: "))
```

Run it once to store the key:

```bash
uv run python configure_secrets.py
```

`set()` creates or replaces the value. The `__main__` guard keeps setup out
of workload imports. For CI, call `api_key.set(os.environ["SERVICE_API_KEY"])`
in the setup script and have your CI secret store supply the variable.

Set `SERVICE_URL` to your service's HTTPS API URL, then call it:

```bash
uv run lazycloud run service:fetch_status "$SERVICE_URL"
```

LazyCloud encrypts secrets at rest and scopes them to the workspace. Your code
can still leak one by printing it or including it in a response. `set()`
returns a record that contains the value, so setup scripts should discard it.

## Rotate or remove a secret

Rotating a secret means running the setup script with the replacement value,
then redeploying so new containers receive it. `create(value)` refuses to
replace an existing secret, which suits a secret whose accidental rotation
would invalidate stored data or tokens. `update(value)` replaces an existing
secret, `get()` reads it, and `delete()` removes it.

Removing a secret name from a workload leaves the stored secret in place until
you delete it.

`Image.with_secrets([...])` supplies build-time credentials.
[Bucket mounts](/concepts/volumes#mount-an-existing-cloud-bucket) name the
secrets holding the access key and secret key.

## From the CLI or dashboard

`uv run lazycloud secret show SERVICE_API_KEY` shows a secret's metadata. See
[secret commands](/cli/storage#lazycloud-secret). The dashboard manages secrets
under Storage.
