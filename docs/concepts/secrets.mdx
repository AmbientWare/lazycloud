---
title: "Secrets"
description: "Workspace-scoped secrets injected into workloads as environment variables."
---

Secrets store credentials — API keys, tokens, connection strings — encrypted
at rest and scoped to a workspace. Workloads reference secrets by name and
receive them as environment variables; secret values never appear in
deployment specs, logs, or the dashboard.

## Managing secrets

```bash
lazycloud secret create OPENAI_API_KEY <value>
lazycloud secret list
lazycloud secret show OPENAI_API_KEY            # metadata only
lazycloud secret show OPENAI_API_KEY --reveal   # prints the value
lazycloud secret modify OPENAI_API_KEY <new-value>
lazycloud secret delete OPENAI_API_KEY
```

From Python:

```python
from lazycloud import Secret

secret = Secret("OPENAI_API_KEY")
secret.create("<value>")     # or .set(...) / .update(...)
value = secret.get()
secret.delete()
```

## Using secrets in workloads

Pass secret names to any workload; each becomes an environment variable with
the same name inside the container:

```python
import os

from lazycloud import App

app = App("assistant")


@app.function(secrets=["OPENAI_API_KEY"])
def complete(prompt: str) -> str:
    api_key = os.environ["OPENAI_API_KEY"]
    ...
```

Secrets are also used by [image builds](/concepts/images) via
`Image.with_secrets([...])` and by
[cloud bucket mounts](/concepts/volumes#cloud-buckets), which reference
credential secrets by name.

<Warning>
  Secret keys are currently encrypted with AES-GCM using a database-resident
  workspace key; KMS envelope encryption is not yet available. See
  [Known limitations](/reference/limitations).
</Warning>
