---
title: "Secrets"
description: "Give remote workloads API keys and passwords without putting credentials in source code."
---

Store a credential once in your workspace, then name it on the workloads that
need it. LazyCloud injects each selected secret as an environment variable.

## Store a credential

In Bash, read your key without putting its value in shell history:

```bash
read -rsp "API key: " SERVICE_API_KEY; echo
lazycloud secret create SERVICE_API_KEY "$SERVICE_API_KEY"
unset SERVICE_API_KEY
```

Check that it exists:

```bash
lazycloud secret show SERVICE_API_KEY
```

This prints metadata. `--reveal` prints the value, so keep it out of shared
terminal recordings and logs. You can also manage secrets under Storage in
the dashboard.

## Use it in a function

Save this as `service.py`. Set `SERVICE_URL` to your service's HTTPS API URL
before running it.

```python
import os
import urllib.request

from lazycloud import App

app = App("service_client")


@app.function(secrets=["SERVICE_API_KEY"], retries=0)
def fetch_status(url: str) -> str:
    request = urllib.request.Request(
        url,
        headers={"Authorization": f"Bearer {os.environ['SERVICE_API_KEY']}"},
    )
    with urllib.request.urlopen(request, timeout=30) as response:
        return response.read().decode("utf-8")
```

```bash
lazycloud run service:fetch_status "$SERVICE_URL"
```

Only workloads that name `SERVICE_API_KEY` receive it. Secrets are encrypted
at rest and scoped to the workspace. Your code can still expose a secret by
printing it or including it in a response.

## Rotate or remove a secret

Read the replacement into a variable, then update it:

```bash
read -rsp "New API key: " SERVICE_API_KEY; echo
lazycloud secret modify SERVICE_API_KEY "$SERVICE_API_KEY"
unset SERVICE_API_KEY
```

Redeploy workloads that need the replacement so new containers receive it.
Delete an unused secret with `lazycloud secret delete SERVICE_API_KEY`.

## Manage secrets from Python

```python
import os

from lazycloud import Secret

secret = Secret("SERVICE_API_KEY")
secret.set(os.environ["SERVICE_API_KEY"])
```

`set()` creates or replaces the value. `create()` creates it,
`update()` replaces it, `get()` reads it, and `delete()` removes it.

For build-time credentials use `Image.with_secrets([...])`. For
[bucket mounts](/concepts/volumes#cloud-buckets), configure the names of the
secrets holding the access key and secret key.
