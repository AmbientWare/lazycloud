`@app.task_queue` registers a callable for asynchronous background work.
Submissions are durable tasks processed by queue workers; the callable keeps
its typed Python signature.

```python
from lazycloud import App, Image

app = App("pipelines")
image = Image(python_version="3.12")


@app.task_queue(name="summaries", image=image, workers=1, retries=2)
def summarize(values: list[int]) -> dict[str, int]:
    return {"count": len(values), "total": sum(values)}
```

Task queues default to `cpu=1.0`, `memory="128Mi"`, `timeout=3600`,
`retries=3`, `workers=1`, `keep_warm_seconds=10`, `max_pending_tasks=100`,
and `authorized=True`.

## Submitting work

`put` submits one task and returns a handle; `put_many` submits a batch:

```python
handle = summarize.target("deployed").put([1, 2, 3])
result = handle.result(wait=True, timeout_seconds=120)
print(handle.task_id, result.ok, result.value)

batch = summarize.target("deployed").put_many([[1, 2], [3, 4]])
```

`target(...)` accepts `"auto"`, `"served"`, or `"deployed"` plus
`deployment_name`/`deployment_version`, exactly like endpoints. `.local(...)`
runs the callable in-process for tests.

Results carry `ok`, `value`, `error`, and `status`; failed tasks are also
visible with `lazycloud task list` and `lazycloud task result <task-id>`. See
[Tasks and logs](/concepts/tasks-and-logs).

## Retries

- `retries` sets the retry attempt count and `retry_delay_seconds` the delay
  between attempts.
- `retry_for` restricts retries to specific exception types:

  ```python
  @app.task_queue(retries=2, retry_for=[TimeoutError, ConnectionError])
  def fetch(url: str) -> str: ...
  ```

- `retry_policy` accepts a full `RetryPolicy` (`max_attempts`,
  `delay_seconds`, `backoff` of `"fixed"` or `"exponential"`,
  `max_delay_seconds`) when you need backoff control.

## Workers and autoscaling

| Option | Description |
| --- | --- |
| `workers` | Initial worker container count. |
| `keep_warm_seconds` | Seconds an idle worker stays alive before scaling down. |
| `max_pending_tasks` | Backpressure limit on queued submissions. |
| `autoscaler` | `QueueDepthAutoscaler` scaling workers with queue backlog. |
| `checkpoint_enabled` | Restore workers from a snapshot instead of cold-starting. |

```python
from lazycloud import QueueDepthAutoscaler


@app.task_queue(
    name="transcode",
    autoscaler=QueueDepthAutoscaler(
        queue="transcode",
        min_containers=0,
        max_containers=10,
        tasks_per_container=1,
    ),
)
def transcode(path: str) -> str: ...
```

## Lifecycle hooks

Task queues accept the same lifecycle hooks as functions — `on_start`,
`on_running`, `on_success`, `on_error`, `on_retry`, `on_failure`,
`on_cancelled`, `on_timeout`, `on_finish` — invoked by the workload runner as
each task progresses. See [Functions](/concepts/functions#lifecycle-hooks).

## Serve and deploy

`lazycloud serve module.py:summarize` previews the queue with live logs;
`lazycloud deploy module.py:summarize` (or `summarize.deploy()`) creates the
durable deployment.
