A decorator on your Python function names the packages, CPU, memory, GPU, and
storage it needs, so whoever writes the function, you or an agent, also writes
where it runs. LazyCloud builds the container, runs it on cloud CPUs and GPUs,
and stops it when the work is done. You pay per second while it runs.

```python
from lazycloud import App, Image
from pydantic import BaseModel

app = App("reports")


class Summary(BaseModel):
    total: float
    mean: float


@app.function(image=Image(python_version="3.12"), cpu=2, memory="4Gi")
def summarize(amounts: list[float]) -> Summary:
    return Summary(total=sum(amounts), mean=sum(amounts) / len(amounts))
```

## Develop locally, test in the cloud, deploy

The same file runs at every stage, without code changes:

```bash
uv run pytest                                           # tests call summarize.local(...)
uv run lazycloud run reports:summarize '[12.5, 30, 8]'   # run once in the cloud
uv run lazycloud deploy reports                         # keep it running in the cloud
```

Each step is one command with no browser or prompt. Add `--json` and the result
arrives on stdout as one JSON document, logs go to stderr, and a failure exits
nonzero. An agent can run the whole loop and read the outcome the same way you
do.

## What you can ship

- [APIs](/concepts/endpoints): a function as an HTTPS endpoint, or a full
  FastAPI app.
- [Jobs](/concepts/functions): tests, evals, data processing, and GPU work,
  fanned out across containers.
- [Background work and crons](/concepts/schedules): tasks with retries,
  cancellation, and live logs.
- [Agent sandboxes](/concepts/sandboxes): isolated containers for running your
  agent's code and tests.
- [Dev machines](/concepts/dev-machines): a devbox you reach over SSH, whose
  disk keeps its files between sessions.
