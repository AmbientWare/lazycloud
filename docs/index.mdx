LazyCloud is infrastructure for agentic engineering. Building with agents is
fast, and deploying with LazyCloud is too.

Your workloads are defined in Python next to the code they run. A decorator
names the packages, CPU, memory, GPU, and storage a function needs, so the agent
that writes the function also writes where and how it runs, in the same edit.
LazyCloud builds the container, uploads the code, runs it, and stops it when the
work is done. You pay per second while a container runs.

```python
from lazycloud import App, Image

app = App("reports")


@app.function(image=Image(python_version="3.12"), cpu=2, memory="4Gi")
def summarize(amounts: list[float]) -> dict[str, float]:
    return {"total": sum(amounts), "mean": sum(amounts) / len(amounts)}
```

## Develop locally, test in the cloud, deploy

The same file runs at every stage, without code changes:

```bash
uv run pytest                                           # develop locally with summarize.local(...)
uv run lazycloud run reports:summarize '[12.5, 30, 8]'   # test once on cloud compute
uv run lazycloud deploy reports                         # deploy for your app to call
```

Each step is one command with no browser or prompt. Add `--json` and the result
arrives on stdout as one JSON document, logs go to stderr, and a failure exits
nonzero. An agent can run the whole loop and read the outcome the same way you
do.

## What you can ship

- [APIs](/concepts/endpoints): a function as an HTTPS endpoint, or a full
  FastAPI app.
- [Jobs](/concepts/functions): tests, evals, data processing, and GPU work,
  fanned out across containers.
- [Background work and crons](/concepts/schedules): tasks with retries,
  cancellation, and live logs.
- [Agent sandboxes](/concepts/sandboxes): isolated containers for running your
  agent's code and tests.

## Point your agent at these docs
