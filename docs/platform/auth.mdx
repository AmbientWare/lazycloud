## Sign in to the dashboard

Go to [lazycloud.dev](https://lazycloud.dev) and continue with GitHub. The first
sign-in creates your account and a workspace you own. There is no password;
GitHub is the only way in.

Your name, email, and avatar come from GitHub and refresh each time you sign
in. A browser session lasts 12 hours. Signing out ends that session only; the
CLI and other browsers stay signed in.

## Sign in from the CLI

```bash
lazycloud login
```

The CLI prints a link and a code. Open the link, confirm the code matches what
your terminal shows, and approve. The code expires if you wait too long; run
`lazycloud login` again to get a new one.

Approval signs the CLI in as you. It can reach every workspace your account
belongs to, and it stores its credential in `~/.lazycloud/config.yaml`.

## Workspaces

A workspace holds apps, deployments, tasks, secrets, volumes, and queues. It is
the boundary between one project and another. Your account can own or belong
to several workspaces, and the same sign-in reaches all of them.

The CLI acts in one workspace at a time:

```bash
lazycloud workspace list
lazycloud workspace use <name>
lazycloud workspace rename <new-name>
```

To act in a different workspace for one command, pass `--workspace <name>`.
Create new workspaces from the workspace menu in the dashboard. Members of a
workspace are managed from the same menu, where an owner or administrator
invites people by email, changes roles, and removes members. The invitation
email carries a link, and opening it joins the workspace as whichever account
you are signed in as, so it does not have to be the address the invitation was
sent to. Keep the link to yourself: anyone who opens it takes the seat. An
administrator can resend an invitation, which replaces the earlier link, or
withdraw it. Anyone but the owner can leave a workspace from the members
dialog.

Access tokens, your connected AWS account, joined machines, custom domains, and
your plan belong to your account rather than to a workspace. They apply to
every workspace you own.

## CI and scripts

Create an access token in the dashboard under Settings, then Tokens. Give it a
name and an expiry (1 day to 90 days, or never). Copy the value when it is
shown; it is not shown again. A token has the same reach as your sign-in, so
treat it like a password. Deleting a token stops it working immediately.

Give the token to the CLI through the environment:

```bash
export LAZYCLOUD_TOKEN="<token>"
export LAZYCLOUD_WORKSPACE="<workspace-name>"
lazycloud deploy app.py:app
```

`LAZYCLOUD_TOKEN` and `LAZYCLOUD_WORKSPACE` override whatever the CLI has
stored, so a CI job needs no `lazycloud login` step. `LAZYCLOUD_HOME` moves the
state directory away from `~/.lazycloud` if the job cannot write there.

To store a token instead of exporting it each time:

```bash
lazycloud login --token "<token>" --workspace <workspace-name>
```

Use the token as a bearer credential when calling an authorized endpoint or
pod directly:

```bash
curl "<endpoint-url>" -H "Authorization: Bearer $LAZYCLOUD_TOKEN"
```

### Profiles

The CLI can keep more than one sign-in, for example one per workspace or one
for an automation token. Each is a profile, and one profile is active at a
time:

```bash
lazycloud login --profile ci --token "<token>" --workspace staging --no-activate
lazycloud profile list
lazycloud profile activate ci
lazycloud profile current
lazycloud profile delete ci
```

`LAZYCLOUD_PROFILE=<name>` selects a profile for one command without changing
the active one.
