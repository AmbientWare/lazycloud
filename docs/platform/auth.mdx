title: "Sign-in and workspaces"
description: "Sign in to the dashboard and the CLI, work in workspaces, and authenticate CI and scripts."

Browser sign-in suits your own development, and access tokens suit CI and
scripts. Resources belong to the workspace selected when you create them.

## Sign in to the dashboard

Go to [lazycloud.dev](https://lazycloud.dev) and continue with GitHub. The first
sign-in creates your account and a workspace you own. There is no password.
GitHub is the only way in.

Your name, email, and avatar come from GitHub and refresh each time you sign
in. A browser session lasts 12 hours. Signing out ends only that session. The
CLI and other browsers stay signed in.

## Workspaces

A workspace holds apps, deployments, tasks, secrets, volumes, and queues. It
separates one project from another. Your account can own or belong to several
workspaces, and the same sign-in reaches all of them.

The CLI acts in one workspace at a time:

```bash
uv run lazycloud workspace list
uv run lazycloud workspace use <name>
uv run lazycloud workspace rename <new-name>
```

`--workspace <name>` acts in a different workspace for one command.

The dashboard's workspace menu creates workspaces and manages members. An owner
or administrator invites people by email, changes roles, and removes members.
The invitation email carries a link. Opening it joins the workspace as
whichever account you are signed in as, even if that account uses a different
address from the one invited. Anyone who opens the link takes the seat. An
administrator can withdraw an invitation or resend it, which replaces the
earlier link. Anyone except the owner can leave a workspace from the members
dialog.

Access tokens, your connected AWS account, joined machines, custom domains, and
your plan belong to your account rather than to a workspace. They apply to
every workspace you own.

## CI and scripts

Access tokens come from the dashboard under Settings, then Tokens. Each has a
name and an expiry between 1 and 90 days, or no expiry. The dashboard shows the
value only once. A token has the same reach as your sign-in, so it needs the
care of a password. Deleting a token stops it working immediately.

CI injects the token from its secret store as `LAZYCLOUD_TOKEN`. For an
interactive Bash session:

```bash
read -rsp "LazyCloud token: " LAZYCLOUD_TOKEN; echo
export LAZYCLOUD_TOKEN
export LAZYCLOUD_WORKSPACE="<workspace-name>"
uv run lazycloud deploy app:app
```

`LAZYCLOUD_TOKEN` and `LAZYCLOUD_WORKSPACE` override whatever the CLI has
stored, so a CI job needs no `lazycloud login` step. `LAZYCLOUD_HOME` moves the
state directory away from `~/.lazycloud` if the job cannot write there.

To store a token instead of exporting it each time:

```bash
uv run lazycloud login --token "$LAZYCLOUD_TOKEN" --workspace <workspace-name>
```

An authorized endpoint or pod takes the token as a bearer credential:

```bash
curl "<endpoint-url>" -H "Authorization: Bearer $LAZYCLOUD_TOKEN"
```

### Profiles

A profile is a separate stored sign-in, for another account or an automation
token. Switching workspaces within one account only needs `workspace use`.
See [`lazycloud profile`](/cli/auth#lazycloud-profile).
