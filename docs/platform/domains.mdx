---
title: "Custom domains"
description: "Serve an endpoint or ASGI app from a hostname you own."
---

Every deployed HTTP workload gets a LazyCloud hostname. On Team and Business plans you
can also use a hostname you own. Domains belong to your account and
are available to every workspace you own.

## Register the domain

```bash
lazycloud domain add app.acme.com
```

The command prints a CNAME record to create at your DNS provider, and any
records needed to prove you own the name. Create them, then check:

```bash
lazycloud domain status app.acme.com
```

Check the reported DNS and certificate status. If verification is pending,
compare the records at your provider with the command's output before checking
again. The hostname can serve HTTPS once its certificate is ready.

The dashboard has the same flow under Settings, then Domains.

## Point a workload at it

Name the hostname on the resource and deploy:

```python
from lazycloud import App

app = App("custom_domain")


@app.endpoint(name="count", methods=["POST"], domain="app.acme.com")
def count_words(text: str) -> dict[str, int]:
    return {"words": len(text.split())}
```

Save this as `custom_domain.py`, replace `app.acme.com` with your verified
hostname, then run `lazycloud deploy custom_domain.py:count_words`.
Send a request using the [endpoint guide](/getting-started/first-endpoint),
with your custom URL. The endpoint still requires authentication by default.

`domain` is accepted by `@app.endpoint`, `@app.asgi`, and `@app.realtime`.
The hostname must be the registered domain or a name under it.

## Remove it

```bash
lazycloud domain list
lazycloud domain remove app.acme.com
```

Removing a domain discards its certificate. Deployments keep their LazyCloud
hostnames.
