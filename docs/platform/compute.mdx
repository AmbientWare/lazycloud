description: "Where your workloads run: LazyCloud's compute, your own AWS account, or machines you join."

Use LazyCloud compute to run without managing machines. Choose CPU, memory,
and GPUs in your workload definition. You pay while its container runs,
including startup and idle time.

## Request a GPU

Save this as `compute_demo.py`:

```python
import subprocess

from lazycloud import App

app = App("compute_demo")


@app.function(cpu=2.0, memory="4Gi", gpu="l4", gpu_count=1)
def gpu_name() -> str:
    return subprocess.check_output(
        ["nvidia-smi", "--query-gpu=name", "--format=csv,noheader"], text=True
    ).strip()
```

Run `uv run lazycloud run compute_demo:gpu_name` to print the assigned GPU's name.
Check your GPU access and balance in Settings, then Billing first.

Available GPU models are `t4`, `a10g`, `l4`, `l40s`, `a100-40`, `a100-80`,
`h100`, and `h200`. Pass a list to state a preference, best first, and `"any"`
last to take whatever is free.

Check what your workspace is using:

```bash
uv run lazycloud compute status
uv run lazycloud compute instances
uv run lazycloud compute workloads
```

## Pools

Every workload runs in a pool. The default pool is LazyCloud's own compute.
Connecting an AWS account or joining a machine adds capacity you own, and a
workload reaches it by naming the pool in its definition. For the GPU example,
add `pool="aws"` to the decorator:

```python
@app.function(cpu=2.0, memory="4Gi", gpu="l4", gpu_count=1, pool="aws")
def gpu_name() -> str:
    return subprocess.check_output(
        ["nvidia-smi", "--query-gpu=name", "--format=csv,noheader"], text=True
    ).strip()
```

Use `--pool` on `deploy`, `run`, `serve`, `shell`, or `dev` for an ad hoc override.
To send every workload in a workspace to a pool without naming it each
time, set the workspace default:

```bash
uv run lazycloud compute pools
uv run lazycloud compute policy show
uv run lazycloud compute policy update --default-pool aws
```

## Your own AWS account

On the Business plan you can connect one AWS account. LazyCloud then launches
instances inside your account when a workload asks for that pool, and shuts
them down when they go idle. Your containers run in your account.
AWS bills you for the instances, and LazyCloud charges a management fee based
on compute rates. Workspace volumes still use LazyCloud storage. Volumes and egress are billed the same
as everywhere else.

The connection belongs to your account and serves every workspace you own.

```bash
uv run lazycloud cloud connect aws --account-id 123456789012
```

Authorize the connection with your AWS profile. The command submits a
CloudFormation stack that creates the management role and network:

```bash
uv run lazycloud cloud authorize --profile YOUR_AWS_PROFILE
uv run lazycloud cloud status
```

Check the CloudFormation stack's events in your AWS account if authorization
has not completed. After the stack finishes, run `uv run lazycloud cloud validate`,
then `uv run lazycloud cloud status` to read the result. The dashboard shows the same
connection under Settings, then Compute. Once ready, select its pool on a workload.

LazyCloud manages instance selection, regions, capacity limits, warm workers,
idle shutdown, and root disks. These settings apply to every workspace the
connection backs. Choose CPU, memory, GPU, and pool on each workload.

If the authorization stops working, for example after a role change in AWS,
`uv run lazycloud cloud status` says so. `uv run lazycloud cloud reconnect` starts a
replacement authorization, and `uv run lazycloud cloud validate` rechecks the current
one. `uv run lazycloud cloud disconnect` drains instances and removes the connection;
add `--wait` to block until it is gone.

## Your own machines

You can join a Linux server you own as capacity for every workspace you own.
This suits an on-premises GPU box, a bare-metal host, or a VM. Containers on
your own machines are not charged compute; volumes and egress still are.

The host needs:

- Linux on amd64 or arm64, with systemd and root or sudo access.
- A rootful Docker daemon.
- Outbound DNS and TCP port 443 for HTTPS and authenticated TLS connections.
  No inbound port, port forwarding, or static IP is needed.

Run the join on the machine itself:

```bash
uv run lazycloud machine join --pool on-prem --gpu a100-80 --max-gpus 4 --max-cpu 32 --max-memory 128Gi
```

The command runs the agent in the foreground. Add `--background` to install a
service that keeps running after the terminal closes. The machine joins the pool
you name, or `self-hosted` if you name none, and creates the pool if it is new.

A pool is removed after its last machine leaves; going offline does not remove
a machine. Workloads targeting a removed pool fail until a machine joins it
again.

The dashboard has the same flow under Settings, then Compute, then Join a
machine, and shows the host checks as they pass. Select that pool with
`--pool on-prem` when running your workload.

```bash
uv run lazycloud machine list
```

When retiring a machine, finish its active workloads and remove the exact
machine ID with `uv run lazycloud machine remove <machine-id>`.
