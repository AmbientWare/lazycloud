The dashboard is served at your control plane URL. It is also where device
login codes from `lazycloud login` are approved.

## Surfaces

| Section | What it shows |
| --- | --- |
| **Apps** | Every app with its workloads, recent activity, deployment version history, lifecycle actions (stop/start/scale/delete), pod instances, latency panels, and a request playground for invoking workloads from the browser. |
| **Tasks** | Workspace-wide task history with per-task detail: status, timing, retries, result, and logs. |
| **Sandboxes** | Running sandboxes with an in-browser terminal, file browser, process list, and container lifecycle/lineage views. |
| **Storage** | Volumes, secrets, and the queue/map collections, with inspectors and links back to the workloads that use them. |
| **Usage** | Cost and usage activity over time, broken down by app. |
| **Settings** | Workspace settings: compute policy, the AWS cloud connection dialog, and joining self-hosted machines. |

Rendering failures degrade to per-panel error states with a retry affordance,
so one failing panel does not take down the dashboard.
